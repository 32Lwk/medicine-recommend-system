## 📋 概要

このシステムは、症状を入力すると適切な市販薬を提案し、薬の飲み合わせや注意点についてアドバイスを提供するAIシステムです。ルールベースとAIを組み合わせたハイブリッド推奨システムを採用し、安全性と監視機能を大幅に強化した最新版です。

## 🚀 主要機能

### 🔄 マルチインスタンス対応（2025年11月5日追加）
- **PostgreSQLベースのセッション管理**: 複数インスタンス間でセッションデータを共有
- **グローバル状態の同期**: AI_AUTO_REPLY、ADMIN_MODE、MANUAL_REPLY_QUEUEをDBで管理
- **Render Manual Scaling対応**: 2-3台のインスタンスで同時接続15台に対応
- **自動フォールバック**: DB接続失敗時はメモリベースの動作にフォールバック

### ✨ ハイブリッド推奨システム（2025年12月5日更新）
- **ルールベース推奨**: 全医薬品種類に対して透明性の高いルールベースアルゴリズムを適用（SYMPTOM_DICTIONARYから動的判定）
- **ChatGPTフォールバック廃止**: ルールベース推奨失敗時のChatGPTフォールバック機能を廃止し、詳細なエラーメッセージを表示（不十分で不適切な回答を防止）
- **NLU段階のChatGPTフォールバック**: 症状抽出（NLU）段階では、ルールベースNLUの信頼度が低い場合（症状0個または信頼度0.3未満）のみChatGPT APIを使用して症状を抽出
- **インフルエンザ検出**: 高熱（38.5度以上）+ 複数の風邪症状でインフルエンザリスクを検出し、アスピリン含有医薬品を自動除外
- **症状特異性ペナルティ**: 単一症状時に複合薬（総合感冒薬など）にペナルティを適用し、特化薬を優先
- **効能テキスト正規化**: 効能効果をNFKC正規化・小文字化し、症状語との突合精度を向上
- **症状適合度の強化**: 同義語も含めた症状マッチングで局所治療薬や総合感冒薬を適切に評価
- **複合症状ボーナスの拡充**: 咳＋痰、鼻水＋鼻づまり、のど＋発熱など代表的な症状の組み合わせを加点
- **のど局所治療薬の優遇**: のど症状がある場合にトローチ・うがい薬等へボーナスを付与し、年齢制限が緩い製品を優先
- **リスク成分フィルタリング**: ヒマシ油、センナ、アスピリンなどの高リスク成分を検出し、単一症状時は除外、複数症状時は減点方式で対応
- **部位特異的製品の検出（2025年12月5日追加）**: デリケート部位・頭皮・のど専用製品を検出し、部位不一致時にペナルティを適用
- **ChatGPTによる症状詳細質問生成（2025年12月5日追加）**: 推奨前に症状とユーザー情報のみを考慮して、ChatGPTが症状の詳細に関する質問を自動生成
- **特殊用途医薬品フィルタリング**: 食あたり専用、便秘限定など特殊用途医薬品を適切にフィルタリング

### 🔍 安全性機能（大幅強化）
- **年齢制限チェックの厳格化**: 
  - 乳児（0-3歳）: 絶対禁忌 - 医師受診必須
  - 幼児（3-7歳）: 医師相談必須
  - 小児（7-15歳）: 注意が必要
  - 高齢者（65歳以上）: 注意が必要
- **妊娠・授乳中チェックの強化**: 
  - 全医薬品種類で医師受診必須
  - 医薬品種類別の制限情報を詳細化
- **Red Flag症状検出**: 重篤な症状を即座に検出し医師相談を推奨
- **症状期間チェック**: 1週間以上継続する症状は医師相談を推奨
- **アレルギー成分照合の精度向上**: 成分名正規化辞書による高精度照合
- **相互作用チェックの詳細化**: リスクレベル別の警告システム

### 🔒 セキュリティ機能
- **プロンプトインジェクション対策**: 850以上の攻撃パターンによる多層防御システム
- **医療用語辞書保護**: 500語以上の症状・医薬品用語で正常な入力を保護（誤検知率0%）
- **危険度スコアリング**: 0-100スコアによる攻撃の危険度判定
- **段階的ロールアウト**: Phase 1（ログのみ）→ Phase 3（完全保護）
- **JSON解析の安全性強化**: スキーマ検証と悪意あるペイロードの検出
- **セキュリティ監視**: リアルタイムログとアラート機能
- **自殺・自傷検出**: 70以上の危機関連ワード検出と相談先提案

詳細なセキュリティ実装については [SECURITY_IMPLEMENTATION.md](SECURITY_IMPLEMENTATION.md) および**セキュリティ機能詳細**セクションを参照してください。

### 💬 インテリジェント質問機能（2025年12月5日更新）
- **不足情報の自動検出**: 年齢・性別・妊娠状態などの重要情報が不足している場合に質問
- **優先度別質問**: Critical → Important → Optional の順で段階的に質問
- **ChatGPTによる症状詳細質問生成（2025年12月5日追加）**: 推奨前に症状とユーザー情報のみを考慮して、ChatGPTが症状の詳細に関する質問を自動生成
  - 基本情報（年齢、性別、妊娠状態、アレルギー、服用中薬、期間）に関する質問は生成しない
  - 症状の詳細（部位、原因、程度、経過など）に関する質問を生成
  - 各質問に優先度（critical, important, optional）を自動付与
  - 質問数は制限なし（ChatGPTが適切な数を自動生成、通常3-5問程度）
  - ルールベースの`AMBIGUOUS_SYMPTOMS`辞書は削除し、ChatGPTによる質問生成に統一
- **critical_questions統合表示**: ChatGPT生成の症状詳細質問（critical_questions）と追加質問（additional_questions）を統合して表示
- **表示順序**: 推奨 → アドバイス → 質問の順で表示（読みやすさを優先）
- **既存入力欄の活用**: 追加質問への回答やその他の情報は、既存のメッセージ入力欄から送信可能
- **セッション管理**: ユーザーの回答を記憶し、重複質問を回避
- **推奨継続**: 症状詳細質問が生成されても推奨を継続（症状が検出されていない場合のみ推奨を中断）
- **質問応答システム**: ユーザーからの直接的な質問に対するAI自動応答
  - ドーピング関連質問への専門的回答
  - 医薬品の安全性に関する質問対応

## セットアップ

### 1. 必要なライブラリのインストール

```bash
pip install -r requirements.txt
```

### 2. OpenAI APIキーの設定

**環境変数を使用（推奨）**

**Windows PowerShellの場合：**
```powershell
# 永続的な設定
[Environment]::SetEnvironmentVariable("OPENAI_API_KEY", "your-api-key-here", "User")
```

**Linux/Macの場合：**
```bash
# 永続的な設定
echo 'export OPENAI_API_KEY="your-api-key-here"' >> ~/.bashrc
source ~/.bashrc
```

**または.envファイルを使用**

1. `python-dotenv`をインストール（`.env`ファイルの読み込みに必要）：
```bash
pip install python-dotenv
```

2. 同じディレクトリに`.env`ファイルを作成：
```env
OPENAI_API_KEY=your-api-key-here
DEEPL_API_KEY=your-deepl-api-key
```

**DeepL APIキーの取得方法**:
- [DeepL API](https://www.deepl.com/pro-api)にアクセス
- アカウントを作成（無料プランあり：500,000文字/月）
- APIキーを取得して`.env`ファイルに設定

**注意**: `.env`ファイルを使用する場合は、`python-dotenv`がインストールされている必要があります。`requirements.txt`に含まれていない場合は、手動でインストールしてください。

### 3. データベースの設定（PostgreSQL、推奨）

**フィードバック機能とセッション管理を使用する場合（マルチインスタンス対応に必須）:**

```bash
# PostgreSQLのインストール（Ubuntu/Debian）
sudo apt-get install postgresql postgresql-contrib

# データベースの作成
sudo -u postgres createdb medicine_feedback

# 環境変数の設定
export DATABASE_URL="postgresql://REDACTED:REDACTED@localhost/medicine_feedback"
```

**データベーススキーマ**:
- `feedback_reports`テーブル: フィードバックデータの保存
- `sessions`テーブル: セッションデータの保存（マルチインスタンス対応）
- `global_state`テーブル: グローバル状態の保存（AI_AUTO_REPLY、ADMIN_MODE、MANUAL_REPLY_QUEUE）

**初期化**:
- アプリケーション起動時に`init_database()`が自動実行され、必要なテーブルが自動作成されます

### 4. データファイルの確認

以下のCSVファイルが配置されていることを確認：
- `otc_medicine_data.csv`: 市販薬のデータベース（7495件）
- `summarized_efficacy_data.csv`: 効能要約データ
- `medicine_side_effects.csv`: 副作用データ
- `medicine_interactions.csv`: 相互作用データ
- `kanpo_medicine.csv`: 漢方薬データ（34種類の漢方薬に対する詳細なルールを含む）

## 使用方法

### Webアプリケーション（メイン）

1. アプリケーションを起動：
```bash
python app.py
```

2. ブラウザで `http://localhost:5000` にアクセス

3. **初回アクセス時のオンボーディングガイド**:
   - 初回アクセス時、5スライドのインタラクティブガイドが自動表示されます
   - 各ステップで該当するUI要素（入力欄、ボタンなど）が視覚的に強調表示されます

4. **症状を入力すると、以下の流れで応答**:
   - 症状に基づく医薬品推奨（上位3件）
   - 各医薬品の詳細情報（成分・効能・年齢制限）
   - 使用上の注意事項
   - 不足情報がある場合は追加質問

5. **使い方ガイドとFAQ**:
   - 右上のℹ️ボタンから「使い方・FAQ」を選択すると、詳細な使い方ガイドとFAQを確認できます
   - 使い方ガイドには、基本的な使い方、便利な機能、アプリの特徴、安全に使うための注意事項が記載されています
   - FAQには、機能・操作、薬剤師要請、薬の推奨、データ・プライバシー、エラー・不具合に関する13の質問と回答が含まれています

## システムアーキテクチャ

### 推奨フロー（2025年12月更新）

```
ユーザー入力
   ↓
セキュリティ検証（security_validator.py）
   ↓ リスクスコア80以上で即停止
言語検出（detect_language）
   ↓
多言語属性抽出（extract_user_attributes_multilingual）
   ↓
症状分析（NLU）
   ├─ ルールベースNLU優先（simple_pattern_matching_nlu）
   │   └─ SYMPTOM_DICTIONARYによるマッチング
   └─ ChatGPTフォールバック（信頼度0.3未満時のみ）
   ↓
インフルエンザリスク検出（detect_influenza_risk）
   ↓
ルールベース推奨（rule_based_medicine_recommendation）
   ├─ 全医薬品種類対応（SYMPTOM_DICTIONARYから動的判定）
   ├─ 候補医薬品フィルタリング
   │   ├─ 特殊用途医薬品除外
   │   ├─ リスク成分チェック（アスピリン・ヒマシ油・センナ等）
   │   └─ インフルエンザ時はアスピリン含有医薬品を除外
   ├─ 二段階スコアリング
   │   ├─ 簡易スコアリング（上位N×250件を選別）
   │   └─ 詳細スコアリング（選別された候補のみ）
   ├─ スコア正規化（Min-Max正規化 + 非線形変換）
   └─ 推奨後の検証処理
       ├─ リスク成分再チェック
       ├─ インフルエンザ適合性確認
       └─ 低スコア候補の警告表示
   ↓
安全性チェック（check_safety_contraindications）
   ├─ 年齢制限チェック（0-3歳: 絶対禁忌、3-7歳: 医師相談必須）
   ├─ 妊娠・授乳中チェック（全医薬品種類で医師受診必須）
   ├─ Red Flag症状チェック（重症疑い症状検出時は即停止）
   └─ 症状期間チェック（1週間以上: 医師受診推奨）
   ↓
使用上の注意自動生成（ChatGPT、キャッシュ機能付き）
   ↓
パーソナライズドアドバイス生成
   ├─ インフルエンザリスク情報
   ├─ リスク成分警告
   └─ 症状特異性アドバイス
   ↓
不足情報チェック（check_missing_information）
   ├─ 年齢・性別・妊娠状態の確認質問
   └─ ChatGPTによる症状詳細質問生成（critical_questions）
   ↓
表示順序: 推奨 → アドバイス → 質問
   ↓
セッション更新（PostgreSQL） + 推奨結果返却
```

**注意**: ルールベース推奨が失敗した場合（status: 'error', 'no_candidates', 'missing_critical_info'など）は、エラーメッセージを表示し、ChatGPTフォールバックは使用されません（2025年12月5日の更新により、ChatGPTフォールバック機能は完全に廃止されました）。

### ルールベーススコアリング（2025年11月1日更新）

```
合計スコア = 
  症状適合度 (0-1.0) × 0.35
  + 効能特異性 (0-1.0) × 0.25
  + 年齢適合性 (0-1.0) × 0.20
  + 用法簡便性 (0-1.0) × 0.05
  - 副作用リスク (0-1.0) × 0.20
  - 相互作用リスク (0-1.0) × 0.10
  - 症状特異性ペナルティ (0～-0.3)
  - リスク成分ペナルティ (0～-0.5)
```

#### スコア要素の詳細
- **症状適合度**: ユーザーの症状と医薬品の効能の適合度（重み: 0.35）
- **効能特異性**: 医薬品の効能が症状に対してどれだけ特異的か（重み: 0.25）
- **年齢適合性**: ユーザーの年齢と医薬品の年齢制限の適合度（重み: 0.20）
- **用法簡便性**: 医薬品の用法・用量の簡便性（重み: 0.05）
- **副作用リスク**: 医薬品の副作用のリスクレベル（重み: -0.20）
- **相互作用リスク**: 他の薬との相互作用のリスクレベル（重み: -0.10）
- **症状特異性ペナルティ**: 単一症状時に複合薬（総合感冒薬など）に適用されるペナルティ（効能特異性に応じて-0.3～-0.05）
- **リスク成分ペナルティ**: ヒマシ油、センナ、アスピリンなど高リスク成分含有時のペナルティ（-0.5～0）

## 医薬品推奨アルゴリズム詳細

### ⚠️ 安全性確保のための5層防御システム

本システムは、誤った推奨や不適切な推奨を防ぐために、以下の5層の防御機構を実装しています：

1. **Layer 1: 入力検証（セキュリティ）** - リスクスコア80以上で即停止
2. **Layer 2: NLU（症状抽出）** - 症状未検出で推奨中断
3. **Layer 3: 禁忌チェック（エスカレーション）** - 乳児・幼児・妊娠中・授乳中で即停止
4. **Layer 4: スコアリング** - アレルギー検出でスコア0.0（完全除外）
5. **Layer 5: 最終判定** - 上位3件の推奨のみ表示

**重要**: いずれかの層で異常が検出された場合、即座に推奨プロセスを停止または中断し、医師相談を促します。

### 1. システム全体の推奨プロセス

#### 1.1 入力検証とセキュリティチェック
1. **セキュリティ検証** (`security_validator.py`)
   - ユーザー入力を `validate_user_input` で検証
   - リスクスコア計算（0-100）
   - ブロック判定（Phase 3以降、スコア80以上で医薬品推奨を完全停止）

2. **入力サニタイズ**
   - XSS対策のためのテキストサニタイズ
   - プロンプトインジェクション攻撃の検出とブロック

#### 1.2 言語検出と多言語対応
1. **言語検出** (`medicine_logic.py` - `detect_language`)
   - 日本語、英語、中国語、韓国語の自動検出
   - 言語に応じた属性抽出プロンプトの生成

2. **多言語属性抽出** (`medicine_logic.py` - `extract_user_attributes_multilingual`)
   - 言語別のプロンプトを使用した属性抽出
   - 年齢、性別、妊娠・授乳状態、アレルギー、服用中薬などを抽出

#### 1.3 インフルエンザ検出（2025年11月1日追加）
1. **インフルエンザリスク検出** (`rule_based_recommendation.py` - `detect_influenza_risk`)
   - ユーザー入力テキストに「インフルエンザ」キーワードが含まれる場合
   - 高熱（38.5度以上）と複数の風邪症状（2つ以上）が検出された場合
   - 検出時はアスピリン含有医薬品を自動除外
   - パーソナライズドアドバイスにインフルエンザの可能性を記載

### 2. NLU（自然言語理解）プロセス（2025年12月更新）

#### 2.1 ハイブリッドNLUアプローチ (`rule_based_recommendation.py`)
1. **ルールベースNLU優先**
   - `simple_pattern_matching_nlu` を最初に実行
   - 症状辞書（SYMPTOM_DICTIONARY）によるマッチング
   - 重症度修飾語の検出（軽度/中等度/重度）
   - 期間表現の抽出（日数計算）
   - **インフルエンザ検出**: 高熱（38.5度以上）+ 複数の風邪症状を検出
   - 部位情報の抽出（頭皮、デリケート部位、のど、腕、足、手、目、鼻など）

2. **ChatGPTフォールバック（NLU段階のみ）**
   - ルールベースNLUの信頼度が低い場合（症状0個または信頼度0.3未満）のみ ChatGPT API を呼び出し
   - `extract_symptoms_with_gpt` で症状抽出
   - システムプロンプトにインフルエンザ検出の指示を追加（高熱38.5度以上+複数症状で「インフルエンザ疑い」をred_flagsに追加）
   - NLUキャッシュにより同じセッションでの重複抽出を防止（セッション間共有キャッシュも対応）
   - **注意**: 推奨段階でのChatGPTフォールバックは廃止されており、ルールベース推奨失敗時はエラーメッセージを表示

#### 2.2 症状辞書の構造
- **正規名**: 標準的な症状名
- **同義語**: 様々な表記ゆれに対応
- **重症度タグ**: 軽度/中等度/重度
- **医薬品種類**: 該当する医薬品カテゴリ
- **重み**: 症状の重要度（0.7-0.95）

#### 2.3 重症疑い症状（Red Flag）の検出
```
RED_FLAG_SYMPTOMS = {
    "呼吸困難": ["呼吸が苦しい", "息苦しい", ...],
    "高熱": ["38.5度以上", "39度", ...],
    "胸痛": ["胸が痛い", ...],
    "意識障害": ["意識がもうろう", ...],
    ...
}
```
- Red Flag検出時は即座にエスカレーション
- 医師受診が必須となり、医薬品推奨は停止

### 3. ユーザー属性の取得と管理

#### 3.1 属性抽出の優先度
```
Critical属性（推奨前に必須）:
- 年齢: 医薬品選択に必須（ただし推奨は継続可能）
- 症状: 推奨の基礎となる情報

Important属性（推奨品質向上）:
- 性別: 生理痛など性別特異的な症状の判定
- 妊娠・授乳状態: 禁忌チェックに必須

Optional属性（追加安全性）:
- 症状期間: 1週間以上の症状は医師受診推奨
- 服用中の薬: 相互作用チェック
- アレルギー: 禁忌薬の除外
```

#### 3.2 不足情報チェック (`check_missing_information`)（2025年11月7日更新）
1. 年齢が不明の場合
   - 推奨は継続するが、年齢確認の質問を表示
   - 内部処理ではスコアリング用に成人（20歳）を仮設定し、小児専用製剤は候補から自動除外
   - 重要度: important
   
**NLU改善（2025年11月7日）**:
- 活用形対応: 「痛い」「痛く」「痛む」などの動詞活用を自動認識
- 部分一致強化: 症状の語幹マッチングで検出精度を向上

2. 症状が検出されない場合
   - 推奨を中断
   - 重要度: critical

3. 妊娠・授乳状態が不明の場合
   - 女性または性別不明の場合は確認質問
   - 重要度: important

4. 曖昧症状の検出（新規追加）
   - 腹痛、頭痛、咳などの曖昧な症状を検出
   - 具体的な質問を自動生成（AMBIGUOUS_SYMPTOMS辞書から）
   - critical_questionsとして追加質問と統合して表示
   - 推奨は継続（症状が検出されていない場合のみ推奨を中断）
   - 表示順序: 推奨 → アドバイス → 質問（読みやすさを優先）

### 5. スコアリングアルゴリズム（2025年11月1日更新）

#### 5.1 スコアリングウェイト（最適化版）
```python
ENHANCED_SCORING_WEIGHTS = {
    "症状適合度": 0.35,      # 0.30から増加（最重視）
    "効能特異性": 0.25,      # 0.20から増加
    "副作用リスク": -0.20,   # -0.40から緩和（妥当な範囲に調整）
    "年齢適合性": 0.20,      # 0.15から増加
    "用法簡便性": 0.05,
    "相互作用リスク": -0.10, # -0.20から緩和
    "禁忌チェック": -1.0,    # 禁忌薬は完全除外
    "安全性スコア": 0.20
}

# 新規追加・改善（2025年11月7日更新）
- 症状特異性ペナルティ: 単一症状時に複合薬に適用（効能特異性に応じて-0.3～-0.05）
- リスク成分ペナルティ: 高リスク成分含有時に適用（-0.5～0）
- 効能特異性に応じたペナルティ緩和: 特異性が高いほどペナルティを軽減（分散拡大）
- 複数症状（例: のどの痛み＋発熱）では総合感冒薬を優先（+0.25ボーナス）、解熱鎮痛薬は軽微なペナルティ（-0.05）
- 喉症状で液剤シグナル（シロップ・内服液・ドリンク等）が検出された場合は+0.22のボーナスを付与
- 剤形多様性: 同スコアの場合、液剤を1件含めるよう優先選択
```

#### 5.2 各スコアの計算方法

**1. 症状適合度** (`calculate_symptom_match_score`)
```
症状スコア = Σ(症状辞書の重み) / 症状数
- 効能効果テキストに症状名が含まれるかチェック
- 各症状の重み（0.7-0.95）を使用
```

**2. 効能特異性** (`calculate_efficacy_specificity_score`)
```
特異性スコア = (症状マッチ数 / 症状数) × (1.0 - 長さペナルティ × 0.3)
- 効能効果テキストに症状がどれだけ特化しているか
- 100文字を基準とした長さペナルティ
```

**3. 年齢適合性** (`calculate_age_fit_score`)
```
年齢スコア:
- 15歳以上: 1.0（問題なし）
- 7-15歳: 0.7（減点）
- 7歳未満または15歳未満制限: 0.0（除外）
```

**4. 用法簡便性** (`calculate_usage_convenience_score`)
```
服用回数によるスコア:
- 1日1回: 1.0
- 1日2回: 0.8
- 1日3回: 0.6
- 1日4回: 0.4
- それ以上: 0.2
```

**5. 副作用リスク** (`calculate_side_effect_risk_score`)
```
副作用データ（medicine_side_effects.csv）から計算:
- 副作用レベル「高」: -0.8
- 副作用レベル「中」: -0.5
- 副作用レベル「低」: -0.2
- 禁忌条件に該当: 2倍（リスク倍増）
- 妊娠中・授乳中: 1.5倍
```

**6. 相互作用リスク** (`calculate_interaction_risk_score`)
```
相互作用データ（medicine_interactions.csv）から計算:
- 相互作用レベル「高」: -0.8
- 相互作用レベル「中」: -0.5
- 相互作用レベル「低」: -0.2
- 相互作用検出時は最大-0.5に制限（元-0.05から4倍増）
```

**7. 症状特異性ペナルティ** (`calculate_symptom_specificity_penalty`)（最適化版）
```
単一症状時に複合薬（総合感冒薬など）に適用されるペナルティ:
- 効能特異性 < 0.8: ペナルティ -0.3（従来通り）
- 0.8 ≤ 効能特異性 < 0.95: ペナルティ -0.15（50%緩和）
- 効能特異性 ≥ 0.95: ペナルティ -0.05（83%緩和）
- 症状カテゴリ間優先表（SYMPTOM_CATEGORY_PENALTY）で柔軟に設定
- 複数症状の場合はペナルティなし
- 効果: 効能特異性が高い医薬品が適切に評価され、スコア分散が拡大
```

**8. リスク成分ペナルティ**（新規追加）
```
高リスク成分含有時のペナルティ:
- アスピリン: -0.5（インフルエンザリスク時は除外）
- ヒマシ油: -0.4（単一症状時は除外）
- センナ: -0.3（単一症状時は除外）
- コデイン: -0.4（依存性リスク）
- トラマドール: -0.4（依存性リスク）
- 単一症状時は除外、複数症状時は減点方式で警告表示
```

#### 5.3 アレルギー・相互作用チェック
**アレルギー照合** (`check_allergy_contraindication`)
```
1. 成分名正規化辞書を使用（INGREDIENT_NORMALIZATION）
2. 完全一致・部分一致でアレルギー成分を検出
3. 検出時はスコアを0.0に設定（完全除外）
```

**相互作用照合** (`check_drug_interactions`)
```
1. 相互作用データベースから該当組み合わせを検索
2. リスクレベル別の警告メッセージを生成
3. 高リスク相互作用検出時は-0.5に減点
```

#### 5.4 スコア正規化と非線形変換（2025年12月更新）
**Min-Max正規化によるスコア調整**:
```
1. 詳細スコアリング完了後、全候補のraw_scoreの最大値・最小値を計算
2. Min-Max正規化: (raw_score - min) / (max - min)
   - 最小値が0.0、最大値が1.0にマッピングされる
   - 上位の医薬品間の差が保持される
3. 0.5以下のスコアは0.0にマッピング（推奨対象外）
4. 非線形変換（平方根）で差を拡大
   - 正規化後のスコアに平方根を適用し、上位の差を明確化
5. 最終的に0.0-1.0の範囲にクリップ
```

**正規化の効果**:
- 1.0を超えるスコアも正しく正規化され、上位の医薬品間の差が明確になる
- 最小値と最大値を考慮することで、推奨対象全体での相対的な評価が可能
- 非線形変換により、高スコア領域での差が拡大され、最適な医薬品の選出が容易に

### 6. 医薬品推奨の最終判定

#### 6.1 推奨フロー（2025年12月更新）
```
1. インフルエンザリスク検出
   - 高熱（38.5度以上）+ 複数の風邪症状で検出
   - 検出時はアスピリン含有医薬品を除外対象に設定

2. 候補医薬品の取得
   - 症状に基づいて医薬品の種類を推定（SYMPTOM_DICTIONARYから動的判定）
   - 特殊用途医薬品パターンでフィルタリング
   - リスク成分含有チェック（単一症状時は除外、複数症状時は候補に追加）
   - 年齢未回答の場合はスコアリング用に20歳を仮定し、小児専用製品（12歳以下向け表示・坐剤等）は自動除外
   - 該当する医薬品リストを抽出

3. 二段階スコアリング
   - 簡易スコアリング（症状適合度×0.5 + 効能特異性×0.3 + 年齢適合性×0.2 + 症状特異性ペナルティ）
   - 上位N×250件を選別（または簡易スコア0.3以上の候補）
   - 選別された候補のみに詳細スコアリング（6要素）を実行

4. スコア正規化と非線形変換
   - Min-Max正規化: (raw_score - min) / (max - min)
   - 0.5以下のスコアは0.0にマッピング（推奨対象外）
   - 非線形変換（平方根）で上位の差を拡大

5. スコア順にソート
   - 上位N件（デフォルト3件）を選択
   - 剤形多様性を考慮（液剤を優先的に1件含める）

6. 推奨後の検証処理
   - リスク成分の再チェックと警告追加
   - インフルエンザ適合性の再確認
   - 低スコア候補（0.5未満）の警告表示

7. 推奨理由の生成
   - スコア内訳に基づく詳細説明
   - 成分情報、年齢制限、注意事項を含む
   - リスク成分警告、低スコア警告を含む

8. エラーハンドリング（2025年12月5日追加）
   - ルールベース推奨失敗時（status: 'error', 'no_candidates', 'missing_critical_info'など）は、詳細なエラーメッセージを表示
   - ChatGPTフォールバックは使用されない（不十分で不適切な回答を防止）
```

### 9. 誤った推奨を防ぐための安全機構（2025年11月1日更新）

#### 9.0 最新の安全機構追加（2025年11月1日）

**1. インフルエンザ検出とアスピリン除外**
- 高熱（38.5度以上）+ 複数の風邪症状（2つ以上）でインフルエンザリスクを検出
- インフルエンザリスク時はアスピリン含有医薬品を自動除外（ライ症候群リスク回避）
- パーソナライズドアドバイスにインフルエンザの可能性を記載

**2. 症状特異性ペナルティ**
- 単一症状（例：発熱のみ）時に複合薬（総合感冒薬など）にペナルティ（-0.3）を適用
- 症状カテゴリ間優先表（SYMPTOM_CATEGORY_PENALTY）で柔軟に設定
- 特化薬（解熱鎮痛薬など）を優先的に推奨

**3. リスク成分フィルタリング**
- ヒマシ油、センナ、アスピリン、コデイン、トラマドールなどの高リスク成分を検出
- 単一症状時はリスク成分含有医薬品を除外
- 複数症状時は減点方式（-0.4～-0.5）で対応し、警告メッセージを表示

**4. 特殊用途医薬品フィルタリング**
- 食あたり専用、便秘限定、腸内容物排除など特殊用途医薬品を検出
- 症状が特殊用途と完全に一致しない場合は除外

**5. 曖昧症状の質問生成**
- 腹痛、頭痛、咳などの曖昧な症状に対して具体的な質問を自動生成
- critical_questionsとして追加質問と統合して表示（推奨 → アドバイス → 質問の順）
- 曖昧症状が検出されても推奨を継続（症状が検出されていない場合のみ推奨を中断）

**6. 検証関数の分離**
- `_recheck_risk_ingredients`: リスク成分の再チェックと警告追加
- `_check_influenza_compatibility`: インフルエンザ適合性チェック
- `_finalize_recommendations`: 最終推奨の確定処理（責務統合）
- スコアが0.5未満の候補に警告を付与

**7. スコアリング後の再検証**
- 推奨後の検証処理（_finalize_recommendations）で最終チェック
- リスク成分警告の強化（特に単一症状時）
- インフルエンザ適合性の再確認
- 低スコア候補の警告表示

#### 9.1 多層安全性チェック
```
Layer 1: 入力検証（セキュリティ）
  ↓ リスクスコア80以上で即停止

Layer 2: NLU（症状抽出）
  ↓ 症状未検出で推奨中断

Layer 3: 禁忌チェック（エスカレーション）
  ↓ 乳児・幼児・妊娠中・授乳中で即停止

Layer 4: スコアリング
  ↓ アレルギー検出でスコア0.0（完全除外）

Layer 5: 最終判定
  ↓ 上位3件の推奨のみ表示
```

#### 9.2 エスカレーションメカニズム
```
1. 重症疑い症状（Red Flag）検出
   → 即座に医師受診を推奨、医薬品推奨は停止

2. 絶対禁忌の検出
   - 乳児（0-3歳）: 市販薬使用不可
   - 妊娠中: 全医薬品種類で医師受診必須
   - 授乳中: 全医薬品種類で医師受診必須

3. 症状期間の長期化
   - 1週間以上の症状: 医師受診推奨（推奨は継続）

4. 高リスク相互作用
   - 相互作用検出時は-0.5の大幅減点
   - 警告メッセージを表示
```

#### 9.3 アレルギー対応
```
1. 成分名正規化辞書による高精度照合
2. 完全一致・部分一致の両方でチェック
3. アレルギー成分検出時は即座にスコア0.0
4. 推奨リストから完全除外
```

#### 9.4 相互作用対応
```
1. 相互作用データベースによる照合
2. リスクレベル別の警告（高・中・低）
3. 高リスク相互作用検出時は-0.8に減点
4. 推奨リストには含めるが警告表示
```

#### 12.2 二段階スコアリング（2025年11月7日更新）
**高速化と精度の両立**:
- **簡易スコアリング**: 症状マッチ（50%）+ 効能特異性（30%）+ 年齢適合性（20%）+ 症状特異性ペナルティを計算
  - 複数症状時の薬効調整を簡易スコアにも適用（風邪薬 +0.25、解熱鎮痛薬 0.0）
- **上位N×250件の選別**: 簡易スコアで上位750件（N=3の場合）を選別（異なる薬効カテゴリの多様性確保）
- **閾値ベースの選別**: 簡易スコアが0.3以上の候補も含める（高スコア候補の漏れを防止）
- **詳細スコアリング**: 選別された候補のみに詳細スコアリングを実行
- **剤形多様性**: 液剤を優先的に1件含めるよう選択
- **効果**: 効能特異性が異なる薬効カテゴリ間でも適切な比較を実現しつつ、高速性を維持

**処理フロー**:
```
1. 全候補に対して簡易スコアリング（症状適合度×0.5 + 効能特異性×0.3 + 年齢適合性×0.2 + 症状特異性ペナルティ）
2. 簡易スコアで上位N×250件を選別（または簡易スコア0.3以上の候補）
3. 選別された候補のみに詳細スコアリング（6要素）を実行
4. 成分多様性と剤形多様性を考慮して上位N件を選択（液剤を優先的に1件含める）
```

## トラブルシューティング

### APIキーが認識されない場合
1. 環境変数が正しく設定されているか確認
2. `.env`ファイルが正しい場所にあるか確認
3. ファイルの文字エンコーディングがUTF-8か確認
4. プログラムを再起動して環境変数を再読み込み

### Webアプリケーションが起動しない場合
1. Flaskがインストールされているか確認
2. ポート5000、5001が使用されていないか確認
3. ファイアウォールの設定を確認

### CSVファイルが読み込めない場合
1. ファイルが正しい場所にあるか確認
2. ファイルの文字エンコーディングを確認
3. ファイルの権限設定を確認

### エラーが発生した場合
1. `app.log`ファイルでエラーの詳細を確認
2. `log/recommendation_log.jsonl`で推奨履歴を確認
3. デバッグアプリ（`http://localhost:5001`）で状態確認
4. エラーメッセージが永続表示される場合は手動で閉じる

### 502 Bad Gatewayエラーが発生した場合
1. サーバーのメモリ使用量を確認
2. ワーカープロセスの状態を確認
3. タイムアウト設定を確認（現在300秒に設定）
4. ログでワーカーの再起動状況を確認

### WORKER TIMEOUTエラーが発生した場合

**問題**: `gunicorn_config.py`で`timeout = 180`（3分）に設定されているが、実際には約30秒でタイムアウトしている。

**原因**: Renderなどのホスティングサービスでは、プラットフォーム側のタイムアウト設定が優先される場合があります。

**解決方法**:

1. **Renderダッシュボードでの設定確認**:
   - Renderダッシュボードにログイン
   - 該当するWebサービスを選択
   - Settings → Environment セクションを確認
   - 環境変数に`WEB_SERVICE_TIMEOUT`などのタイムアウト設定がないか確認

2. **Renderのサービス設定を確認**:
   - Settings → Advanced セクション
   - 「Health Check Path」や「Health Check Timeout」の設定を確認
   - 必要に応じてタイムアウト値を増加

3. **環境変数の設定**:
   ```bash
   # Renderの環境変数に追加（例）
   GUNICORN_TIMEOUT=180
   ```

4. **gunicorn_config.pyの確認**:
   ```python
   # gunicorn_config.py
   timeout = 180  # 3分（秒単位）
   ```
   この設定が正しく読み込まれているか確認

5. **ログの確認**:
   - Renderのログで「WORKER TIMEOUT」エラーが発生している時間を確認
   - 実際のタイムアウト時間を記録
   - 処理が長時間かかっている原因を特定（ChatGPT API呼び出し、データベースクエリなど）

**注意**: Renderの無料プランでは、タイムアウトが30秒に制限されている場合があります。有料プランへのアップグレードが必要な場合があります。

### セッション管理エラーが発生した場合
1. ブラウザのCookieをクリア
2. ページを再読み込み
3. 新しいセッションで再試行
4. セッション管理の自動復旧機能により自動的に復旧される場合がある

### 使用上の注意が表示されない場合
1. ChatGPT APIキーが正しく設定されているか確認
2. ネットワーク接続を確認
3. ブラウザのコンソールでエラーメッセージを確認
4. 使用上の注意はChatGPTで自動生成されるため、API制限に注意

### スマホでの表示が崩れる場合
1. ブラウザのキャッシュをクリア
2. ページを再読み込み
3. iPhone Safariの場合は「デスクトップ版Webサイトを表示」をオフに設定

### 質問応答が動作しない場合
