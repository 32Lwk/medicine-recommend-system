# GitHub Issue 詳細レポート形式

issue の調査・実装・同期時に、本文またはコメントへ **詳細レポート** を付与するためのテンプレートです。  
ロードマップ同期（#71）や CHANGELOG 反映時もこの形式を推奨します。

---

## 必須セクション

```markdown
## 詳細レポート（YYYY-MM-DD）

### エグゼクティブサマリー
- **結論**: （完了 / 部分完了 / 未着手 / ブロッカー）
- **根拠**: CHANGELOG・コード・テストのいずれか1行

### 調査結果

| 項目 | 2026-06-11 時点 | 現状 | 根拠 |
|------|----------------|------|------|
| （例）実装 | 未 | ✅ | `path/to/file.py` L123 |

### コード・ドキュメント根拠
- ファイル: `src/...` — 1行説明
- CHANGELOG: 2026-06-22「セクション名」
- テスト: `tests/...` — カバー範囲

### 残タスク / リスク
1. （具体的な未完了項目）
2. （ブロッカー・依存 issue）

### 受け入れ条件チェック
- [x] 完了した条件
- [ ] 未完了の条件

### 工数・優先度（更新時）
| 項目 | 値 |
|------|-----|
| 残工数 | Xh |
| 優先度 | P0–P3 |
| 依存 | #NN |

### 関連 issue
- 親: #55
- ブロッカー: #79
```

---

## 運用ルール

1. **CHANGELOG 同期時** — 最終更新日と参照セクションを明記する
2. **クローズ時** — 「クローズ理由」と「残作業の移管先 issue」を必ず書く
3. **部分完了** — 完了%/残工数を定量で更新する（「だいたい」は避ける）
4. **バグ issue** — 再確認日と再現コード（ファイル:行）を記載する
5. **Epic** — sub-issue 状態表を差分更新する
