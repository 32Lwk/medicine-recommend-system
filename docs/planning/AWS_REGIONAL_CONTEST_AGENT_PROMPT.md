## プロダクト概要（正本 — 捏造禁止）

### サービス名・位置づけ

- **チャット型医薬品相談ツール**（`medicine-recommend`）
- **β版・限定試験運用** — 医療機関・診断サービス**ではない**
- 一般用医薬品（OTC）の候補提示・受診目安・注意喚起を、**チャット形式**で提供
- 薬選定の中核は **ルールベーススコアリング**（LLM は NLU 補助・説明生成に限定し、薬名の自由創作を抑制）

### 開発背景（発表者のストーリーに組み込む）

- ドラッグストア勤務経験から、**高齢者の聴力・理解力の差**、**外国人との言語障壁**を実感
- 少子高齢化・訪日外国人増・EC 普及によりセルフメディケーション需要は増加する一方、**適切な医薬品選択の支援不足**が課題

### 主な機能（デモで見せる候補）

| 機能 | 説明 |
|------|------|
| 症状チャット相談 | 自然言語で症状入力 → OTC 候補・注意点 |
| 多言語 | 日本語・英語・中国語・韓国語 |
| アクセシビリティ | 音声読み上げ、文字サイズ調整、WCAG AA 準拠 |
| 安全性 | 危険症状時の受診勧奨、ルールベース推奨 |
| マルチエージェント | Triage → Physical / Concierge / StoreInquiry 等 |

### AWS ステージングで訴求する技術（プレゼン・デモの中心）

**デモ URL `aws.medicine.yutok.dev` は AWS 上で動作するステージング環境。** 本番（GCP）との差分を「AWS ネイティブ機能の実証」として説明する。

| AWS サービス | 用途（ステージング） |
|--------------|---------------------|
| **ECS Express Gateway + Fargate + ALB + WAF** | アプリホスティング・セキュリティ |
| **Amazon Translate** | 多言語翻訳（本番 GCP は DeepL） |
| **Amazon Polly** | 音声読み上げ（本番 GCP は Cloud Text-to-Speech） |
| **Amazon Bedrock Knowledge Base** | Concierge / 医薬品 RAG（Managed KB） |
| **Amazon Comprehend Medical** | 医療テキスト解析（Phase 3） |
| **CloudFront + S3** | 静的アセット CDN |
| **CodePipeline / CodeBuild / ECR** | CI/CD（GitHub main 連携） |
| **CloudWatch / AWS Budgets** | 監視・コスト管理 |

**クロスクラウド構成の説明方針**: 本番安定性（GCP）と AWS ネイティブ試験（ステージング）を**意図的に分離**。同一リポジトリ・同一 Docker イメージで、クラウド固有差分は機能フラグのみ — **他地域展開時の柔軟性**として訴求可。

### 必ず明記する免責・境界

- 医師・薬剤師の診断・指導の**代替ではない**
- β版は専門関係者向け試験運用（一般公開ではない）
- 重篤な症状は**医療機関受診**を推奨

### 1. 地域課題調査（`01-regional-challenges.md`）

**北海道・東北7県それぞれ**について、テーマ「住民の暮らしを豊かにするデジタルサービス」と **OTC / セルフメディケーション / 医療アクセス** の交点で調査・整理する。

#### 各県の記載テンプレート（7回繰り返す）

```markdown
## [県名]

### 地域特性（1〜2文）
### 関連する統計・公開データ（出典 URL 必須）
### 住民生活の具体的課題（3〜5 bullet）
### 本サービスとの接点（1〜2文）
### デジタル化の機会（1 bullet）
```

#### 調査観点（最低限カバー）

- **高齢化率・人口減・過疎** — 薬局・ドラッグストアへのアクセス、在宅・単身世帯
- **医療・薬局の偏在** — 過疎地の受診・相談機会、登録販売者・薬剤師の人手不足
- **観光・訪日外国人** — 北海道・東北の観光地での言語障壁、急な体調不良
- **気候・季節要因** — 冬季の外出抑制、花粉・インフルエンザ等の季節症状
- **デジタルデバイド** — 高齢者のスマホ利用率、ICT 支援の必要性

#### ルール

- 統計は **政府統計・総務省・厚労省・観光庁・各県オープンデータ** 等の**出典付き**
- 出典不明・推測のみの数字は書かない（「〜と考えられる」は可、ただし根拠を添える）
- 7県を**均等に**扱い、特定県に偏らない
- 最後に **「7県共通課題」** と **「本サービスが刺さるペルソナ3例」** をまとめる

### 3. デモ台本（`03-demo-script.md`）

**デモ環境: https://aws.medicine.yutok.dev**

#### デモ設計原則

- **所要時間 90〜120秒**（プレゼン5分のうち、デモは約2分以内が理想）
- **事前に動作確認済みシナリオ**のみ（ライブ入力は1パターン + 予備1パターン）
- AWS 機能が体感できる流れを優先（多言語切替 → 症状入力 → 推奨結果 → 音声読み上げ 等）
- β版免責・受診勧奨が自然に見えるシナリオを選ぶ（例: 軽度の頭痛・風邪症状）

#### 必須セクション

```markdown
## 事前準備（発表30分前）
## メインデモシナリオ（ステップ番号・操作・期待画面・話すセリフ）
## サブシナリオ（メイン失敗時・30秒で完結）
## AWS 機能の指差し説明ポイント（Translate / Polly / ECS 等）
## 既知リスクとフォールバック（ネットワーク障害 → スクリーンショット / 録画）
## デモ用アカウント・設定（言語、文字サイズ等）
```

#### 推奨デモシナリオ案（AI が具体化すること）

1. **シナリオA — 高齢者想定（日本語）**: 「昨夜から喉が痛くて微熱があります」→ 推奨 + 音声読み上げ（Polly）
2. **シナリオB — 訪日外国人想定（英語）**: 英語入力 → Translate → 日本語処理 → 英語表示
3. **シナリオC — 受診勧奨（安全設計）**: 危険キーワード含む入力 → 受診推奨カード（短く見せる）

#### フォールバック

- 録画 URL または `docs/planning/aws-contest/demo-fallback/` にスクリーンショット列を準備する手順を記載
- 技育祭用素材 `static/img/about/generated/` に類似 UI 画像があれば参照可
