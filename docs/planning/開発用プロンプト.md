# 開発用プロンプト集

このドキュメントは、**チャット型医薬品相談ツール（medicine-recommend）** の開発・保守時に、AI（Cursor / ChatGPT 等）へ渡して使うプロンプトの例です。コピーして必要に応じて編集してください。

---

## 1. プロジェクト概要を渡すとき（最初に貼ると効果的）

新規チャットや新しいタスクの冒頭で、以下を貼るとコンテキストが伝わります。

```
【プロジェクト】チャット型医薬品相談ツール（medicine-recommend）

- 技術スタック: Python 3.11, Flask, Gunicorn, PostgreSQL（Neon）, OpenAI API, Docker
- 本番: GCP Cloud Run（asia-northeast1）, GitHub 連携で CI/CD
- 構成: app.py はスリムに保ち、ルートは main_routes / admin_routes / api_routes / feedback_routes の Blueprint。ビジネスロジックは src/（core, handlers, services, security 等）に集約。
- 医薬品推奨: ルールベーススコアリング + GPT フォールバックのハイブリッド。LLM は NLU・候補選定に限定。
- 詳細: README.md と docs/planning/GCP移行計画.md を参照。
```

【本アプリケーションの概要（参照用）】

- **名称・目的**: チャット型医薬品相談ツール（medicine-recommend）。症状をチャットで入力すると、一般用医薬品（OTC）の候補を提案し、飲み合わせ・注意点・受診の目安などをアドバイスする。医師・薬剤師の代替ではなく、セルフメディケーションの補助ツール。β版として専門関係者向けに限定公開中。
- **技術スタック**: Python 3.11, Flask, Gunicorn, Neon PostgreSQL, OpenAI API, DeepL API, Docker。本番は GCP Cloud Run（asia-northeast1）、GitHub 連携で CI/CD。
- **構成**: app.py は薄く保ち、ルートは main_routes / admin_routes / api_routes / feedback_routes の Blueprint。ビジネスロジックは src/（core, handlers, services, security, analysis 等）に集約。scripts/ は開発・リファクタ用スクリプトで実行時には読み込まれない。
- **推奨システム**: ルールベーススコアリングを主軸とし、NLU（症状抽出）で信頼度が低い場合のみ GPT を利用するハイブリッド方式。推奨はルールベースで数学的保証を重視。禁忌・妊娠授乳・年齢・成分重複などの多層防御あり。
- **主な機能**: チャット形式の相談、トリアージ（医薬品推奨／カウンセリング／店舗案内／診断名検出／緊急事案等）、多言語対応（DeepL）、セッション管理（DB）、管理画面・手動返信・フィードバック、アクセシビリティ（音声読み上げ・文字サイズ・WCAG AA）、不適切入力のブロック、店舗案内・緊急避妊薬案内など。
- **セキュリティ**: プロンプトインジェクション対策、医療用語辞書、危険パターン検出、診断名検出による受診勧告。docs/security/SECURITY_IMPLEMENTATION.md に詳細あり。
- **ドキュメント**: README.md（統合ドキュメント・長い）、docs/public/アプリ概要.md、docs/planning/GCP移行計画.md、docs/planning/開発用プロンプト.md など。

※ より正確に分析するため、可能であればリポジトリ内の README.md・docs/public/アプリ概要.md・必要に応じて src/ の主要モジュール（chat_handler, rule_based_recommendation, counseling, security 周り）にも目を通してください。

## 使い方のコツ

1. **最初に「プロジェクト概要」を貼る** … スタック・構成・本番環境が伝わり、提案が現実的になります。
2. **対象ファイルや参照ドキュメントを明示する** … どの `docs/` や `src/` を見てほしいか書くと精度が上がります。
3. **既存パターンに合わせる** … 「counseling_prompts の形式に合わせて」などと書くと、一貫した変更になります。
4. **長い指示は箇条書きで** … やること・やってほしくないこと・参照を分けると伝わりやすいです。

必要に応じてこのファイルをコピーし、プロジェクトの進化に合わせて項目を増やしてください。
