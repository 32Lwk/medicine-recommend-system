# 成分評価精査レポート

 対象コミット 40c8a1f（main） 実施日 2026-09-14 対象 成分評価・安全チェック・成分多様性・スコアへの反映 位置づけ スコアリング精査（R2）の続報 

結論から述べます。成分評価は実装されていますが、最終スコアには反映されていません。副作用リスクを「リスクなし（0.0）」から「最悪（−1.0）」に変えても、検証した 6 製品すべてで最終スコアの変化は `0.0000` でした。基本スコアの底上げ規則が、成分評価を含む重み付き和を丸ごと捨てているためです。この底上げは詳細採点候補 2,543 件のうち 2,526 件（99.3%）で発生していました。

あわせて、 NSAIDs の成分重複警告は構造的に発火できない状態です。成分辞書がイブプロフェン・アスピリンを `nsaid` というクラス名に正規化する一方、リスク成分マスタ側には `nsaid` というキーが存在しないため、集合の積が常に空になります。イブプロフェン同士、アスピリン × イブプロフェンのいずれでも警告は出ませんでした。

「正確な医薬品アルゴリズムになっていない」という報告は、成分評価の観点からも裏付けられました。ただし原因は「成分評価のロジックが間違っている」ことではありません。ロジックの多くは意図どおりに書かれており、単体では動作します。問題は 3 層に分かれます。

1. 反映層 — 成分評価の結果が最終スコアに届かない（底上げ規則が吸収する）。
2. 照合層 — 成分名の表記ゆれ・クラス名への正規化・マスタの名称不統一により、照合が空振りする。
3. データ層 — 副作用マスタ 275 行・相互作用マスタ 185 行に対し、OTC 側の異なり成分は 1,331。そもそも突き合わせる先がない成分が多数あります。

実測では、上位 3 件のうち 2 件以上が同一成分を共有するケースが 12 件中 9 件ありました。「不眠で眠れない」では 3 件すべてがジフェンヒドラミン塩酸塩の単剤です。成分多様性を確保する関数は存在しますが、比較対象が各製品の先頭 3 成分に限定されており、総合感冒薬の 4 番目以降にあるジヒドロコデインリン酸塩などは判定に使われていません。

### I1高・安全副作用リスクが最終スコアに一切反映されない

検証
: 副作用リスク関数を差し替え、返り値を 0.0（リスクなし）と −1.0（最悪）に固定して同じ候補を採点しました。

| 製品名 | 医薬品の種類 | 副作用 0.0 | 副作用 −1.0 | 差 |
| --- | --- | --- | --- | --- |
| カロナールA | 解熱鎮痛薬 | 1.3629 | 1.3629 | 0.0000 |
| ロキソニンS | 解熱鎮痛薬 | 1.3629 | 1.3629 | 0.0000 |
| バファリンEX | 解熱鎮痛薬 | 1.3629 | 1.3629 | 0.0000 |
| 新スカイブブロンゴールド錠 | 風邪薬 | 0.2629 | 0.2629 | 0.0000 |
| ソルマックEX2 | 胃腸薬 | 0.2000 | 0.2000 | 0.0000 |
| ドリエル | 睡眠障害 | 0.2500 | 0.2500 | 0.0000 |
原因
: 副作用リスクは `base_score` にしか入りません（`final_score_calculator.py:1367-1374`、重み 0.10）。ところがその直後の底上げ規則が `base_score` の値を条件分岐にしか使わず、結果を定数で置き換えます。

base_score = 0.30·症状適合度 + 0.20·効能特異性 + 0.12·年齢適合性 + 0.03·用法簡便性 + 0.10·副作用リスク + 0.05·相互作用リスク adjusted = 0.55 … 主要解熱鎮痛薬で base < 0.55 （L1951-1954） = 0.50 … それ以外で base < 0.45 （L1962-1966） → 底上げが発動した時点で base_score の中身は完全に捨てられ、 最終スコアは 定数 + 調整項目 だけで決まる

実測した CSV 由来の `base_score` は 0.19〜0.45 に集中しており、ほぼ全候補が底上げの条件に該当します。詳細採点候補 2,543 件のうち底上げが発生したのは 2,526 件（99.3%）でした。

| 医薬品の種類 | 候補数 | 底上げ発生 | 割合 |
| --- | --- | --- | --- |
| 風邪薬 | 1,269 | 1,269 | 100% |
| 外用薬(皮膚) | 392 | 392 | 100% |
| 目薬 | 394 | 390 | 99% |
| 鼻炎用薬 | 191 | 191 | 100% |
| 解熱鎮痛薬 | 175 | 162 | 93% |
| 胃腸薬 | 79 | 79 | 100% |
| 睡眠障害 | 42 | 42 | 100% |
影響
: 副作用リスクだけでなく、症状適合度（重み 0.30）・効能特異性（0.20）・年齢適合性（0.12）・用法簡便性（0.03）・相互作用リスク（0.05）も同じ経路のため、重み付けスコアリングモデル全体が順位に寄与していません。アーキテクチャ文書に記載された重みは、候補の絞り込み（簡易スコア）には効きますが、最終順位には効きません。
参考
: 各項目が最終スコアを動かせる幅を実測した結果は次のとおりです。調整項目が桁違いに大きいことが分かります。

| 項目 | 最終スコアを動かせる幅 |
| --- | --- |
| 症状適合度（重み付け後） | 0.285 |
| 効能特異性（重み付け後） | 0.104 |
| 副作用リスク（重み付け後） | 0.080 |
| 相互作用リスク（重み付け後） | 0.000 |
| 総合感冒薬ボーナス（調整項目） | 1.700 |
| のどボーナス（調整項目） | 0.550 |

ただし上 4 つは底上げ規則により、99.3% の候補で実効幅ゼロになります。
修正案
: 底上げは「下限を設ける」意図だったと読めますが、実装は「値を置き換える」になっています。`adjusted = max(base_score, 0.55)` のように単調性を保つ形に直せば、底上げを維持したまま base_score の差が残ります。あわせて安全側の項目（副作用・相互作用）は base_score ではなく調整項目として、クランプの外で減算することを勧めます。

### I2高・安全 NSAIDs の成分重複警告が構造的に発火できない

検証
: check_ingredient_overlap の発火テスト イブプロフェン 同士 → has_overlap=False 警告なし ⚠ イブプロフェン × ロキソプロフェン → has_overlap=False 警告なし ⚠ アスピリン × イブプロフェン → has_overlap=False 警告なし ⚠ アセトアミノフェン 同士（対照） → has_overlap=True ['アセトアミノフェン'] ジヒドロコデイン 同士（対照） → has_overlap=True ['ジヒドロコデイン']
原因
: `data/ingredient_dictionary.json` に正規名 `NSAID` のエントリがあり、その同義語に `イブプロフェン`・`ロキソプロフェン`・`アスピリン`・`ジクロフェナク` が含まれています。`extract_main_ingredients`（`ingredient_utils.py:19`）はこの辞書で正規化するため、成分トークンがクラス名 `nsaid` に変換されます。

extract_main_ingredients("イブプロフェン") → ['nsaid'] extract_main_ingredients("アスピリン") → ['nsaid'] extract_main_ingredients("ロキソプロフェンナトリウム水和物") → ['ロキソプロフェンナトリウム水和物'] ← 辞書に無く素通り

一方 `RISK_INGREDIENTS_OVERLAP`（`recommendation_constants.py:624-`）のキーは `イブプロフェン`・`ロキソプロフェン`・`アスピリン`・`メフェナム酸` であり、`nsaid` というキーも同義語も存在しません。判定は集合の積（`ingredient_utils.py:104` 付近）で行われるため、積が常に空になります。

さらにイブプロフェンは `nsaid` に、ロキソプロフェンナトリウム水和物は素通りと、正規化の扱いが非対称なため、両者の積も空です。
影響
: NSAIDs は `RISK_INGREDIENTS_OVERLAP` で重大度 `red`、注記に「ロキソプロフェン等、他の NSAIDs との併用は避けてください」と定義されている、システム内で最も重い重複警告です。それが一度も出せません。胃腸障害・腎機能障害・出血傾向のリスクを伴う併用が、警告なしで並びます。
修正案
: 成分辞書からクラス名への正規化（`NSAID` エントリ）を外し、クラス判定は別フィールドで持つ。または `RISK_INGREDIENTS_OVERLAP` に `category` 単位の突き合わせを追加する（すでに各エントリが `category: "nsaid"` を持っているため、成分名ではなく category で重複を判定する方が堅牢です）。

### I4高相互作用リスクが全候補でゼロ

検証
: 10 種類の症状入力で詳細採点された 2,523 候補すべてについて `interaction_risk = 0.0` でした。関数を直接呼ぶと次のようになります。

calculate_interaction_risk_score(ロキソプロフェン含有薬, current_medications=…) ['ワルファリン'] → 0.0 ← 一般名では不一致 ['ワルファリンカリウム'] → 0.0 ['ロキソプロフェン'] → −0.575 ← マスタの表記と一致すれば発火する ['アスピリン'] → 0.0 ['ロキソニン'] → 0.0

相互作用マスタには `ワーファリン`（商品名の旧表記）が登録されており、一般名の `ワルファリン` は存在しません。NSAIDs × ワルファリンは重大度「高」の代表的な組み合わせですが、ユーザーが一般名で申告すると照合できません。
データ側
: 相互作用マスタ 185 行・異なり名称 107 件のうち、 33 件は OTC の成分欄に一度も現れません。`ACE阻害薬`・`MAO阻害薬`・`SSRI`・`SNRI`・`ベンゾジアゼピン`・`ベータ遮断薬`・`クマリン系抗凝血薬`・`オピオイド` といった薬効群名と、`メトトレキサート`・`ジゴキシン`・`シクロスポリン`・`タクロリムス` などの処方薬名です。これらは「OTC 成分 × 処方薬」を想定した設計と読めますが、照合はユーザーの自由入力と突き合わせるため、ユーザーが薬効群名で申告しない限り当たりません。
修正案
: マスタの名称を一般名に統一し、商品名・旧表記は同義語として別途持つ。ユーザー入力は商品名から一般名への解決を挟む（`medicine_brand_resolve.py` が既にあるため流用できる可能性があります）。薬効群名のエントリは、群に属する具体的な薬剤名リストとともに保持する。

### I5高同じ相互作用に対し 2 つの関数が逆の結論を返す

検証
: 候補 = バファリンEX（ロキソプロフェンナトリウム水和物） calculate_interaction_risk_score(['ロキソニン']) → 0.0 （相互作用なし） check_drug_interactions(['ロキソニン']) → True （禁忌レベルを含む 8 件） calculate_interaction_risk_score(['ワルファリン']) → 0.0 check_drug_interactions(['ワルファリン']) → (False, [])

原因は正規化の有無です。`check_drug_interactions`（`scoring_utils.py:1060`）は両辺に `normalize_ingredient_name` を適用しますが、`calculate_interaction_risk_score`（同 874）は適用しません。同じ判断を 2 つの関数が別の基準で行っています。
警告文
: `check_drug_interactions` が返す警告文は、マスタの `説明` 列をそのまま連結します。この列には添付文書の相互作用セクションが丸ごと入っているため、1 件あたり 500〜900 文字、8 件で数千文字の警告になります。実測した冒頭は次のとおりです。

🚨 禁忌レベル: ロキソプロフェンナトリウム水和物とロキソニンの併用は避けてください。 ワルファリン 抗凝血作用を増強するおそれがあるので注意し、必要があれば減量すること。 本剤のプロスタグランジン生合成抑制作用により血小板凝集が抑制され血液凝固能が低下し、 抗凝血作用に相加されるためと考えられている。第Xa因子阻害剤 エドキサバントシル酸塩 水和物等 出血の危険性を増大させるおそれがある。…（以下数百文字）

ユーザーは「ロキソニンを飲んでいる」と伝えただけであり、ワルファリンや第Xa因子阻害剤は服用していません。無関係な薬剤名を含む長文が禁忌警告として提示されます。
修正案
: 2 つの関数を 1 つに統合し、正規化を共通化する。警告文はマスタの `説明` 列をそのまま出さず、要約列を別途持つか、先頭 1 文に限定する。

### I6高全角マイナスの成分が重複警告に一致しない

検証
: CSV の表記 : dl−メチルエフェドリン塩酸塩 （全角マイナス U+2212） 定数の表記 : dl-メチルエフェドリン塩酸塩 （ASCII ハイフン U+002D） 完全一致するリスク成分キー → （なし） 同様に d−クロルフェニラミンマレイン酸塩 も一致しない

`dl−メチルエフェドリン塩酸塩` は実測した重複ペア 8 件すべてに登場する成分です。交感神経刺激成分であり、`RISK_INGREDIENTS_OVERLAP` では重大度 `yellow`、注記に「咳止めや風邪薬に含まれる。交感神経刺激作用の重複に注意」と定義されていますが、一度も警告されませんでした。
修正案
: 成分名の比較前に NFKC 正規化を挟む。前回のスコアリング精査で報告した `医薬品の種類` の全角・半角括弧の不一致（H8）と同じ性質の問題であり、まとめて「CSV 由来文字列は 1 箇所で正規化する」方針に統一するのが有効です。

### I7中アレルギー判定がクラス名に対応せず、正規化も不統一

検証
: check_allergy_contraindication(ロキソプロフェン含有薬, allergies=…) ['ロキソプロフェン'] → (True, 'ロキソプロフェン') ['ロキソプロフェンナトリウム水和物'] → (True, 'ロキソプロフェンナトリウム水和物') ['ピリン系'] → (False, '') ⚠ ['NSAIDs'] → (False, '') ⚠ ['アスピリン'] → (False, '') normalize_ingredient_name の挙動 ロキソプロフェンナトリウム水和物 → 'ロキソプロフェン' （正規化される） ジフェンヒドラミン塩酸塩 → 'ジフェンヒドラミン塩酸塩' （されない） d−クロルフェニラミンマレイン酸塩 → そのまま （されない） トコフェロール酢酸エステル → そのまま （されない）

「ピリン系アレルギー」は日本の OTC で最も一般的な申告のひとつですが、成分名との照合では当たりません。`RISK_INGREDIENTS_OVERLAP` にはイソプロピルアンチピリンのエントリがあり注記に「ピリン系アレルギーの既往がある場合は厳禁」と書かれているため、意図としては扱う想定だったと読めます。

正規化は「ナトリウム水和物」など一部の接尾辞のみに対応しており、「塩酸塩」「マレイン酸塩」「酢酸エステル」「硝化物」は処理されません。
修正案
: 塩・水和物・エステルの接尾辞を一般化して除去する。アレルギー申告はクラス名（ピリン系・NSAIDs・サリチル酸系）を受け付け、`RISK_INGREDIENTS_OVERLAP` の `category` と突き合わせる。

### I8中文字列で渡ると 1 文字ずつ薬剤名として扱われる

### I3高成分多様性の比較が先頭 3 成分に限定されている

原因
: `extract_main_ingredients(ingredients, max_count=3)`（`ingredient_utils.py:19`）の既定値は 3 です。成分重複警告（同 89）だけが `max_count=20` を明示して呼びますが、`ingredient_diversity.py` の 10 箇所（341, 397, 410, 427, 437, 444, 449, 537, 542 ほか）はいずれも既定のまま呼ぶため、各製品の先頭 3 成分しか比較されません。

新スカイブブロンゴールド微粒（CSV 全成分 7 件） アセトアミノフェン / クロルフェニラミンマレイン酸塩 / グアイフェネシン / ジヒドロコデインリン酸塩 / リボフラビン / 無水カフェイン / dl−メチルエフェドリン塩酸塩 多様性判定が見る成分 → ['アセトアミノフェン', 'クロルフェニラミンマレイン酸塩', 'グアイフェネシン'] 比較対象外 → ジヒドロコデインリン酸塩 / 無水カフェイン / dl−メチルエフェドリン塩酸塩

ジヒドロコデインリン酸塩は麻薬性鎮咳成分で、`RISK_INGREDIENTS_OVERLAP` の重大度は `red`、注記は「12 歳未満は使用禁止。風邪薬と咳止めで重複しやすい」です。総合感冒薬では 4 番目前後に並ぶことが多く、多様性判定からは見えません。
実測
: 12 種類の入力で上位 3 件の成分を突き合わせた結果、 9 件で 2 件以上が同一成分を共有していました。

| 入力 | 上位 3 件 | 共有されていた成分 |
| --- | --- | --- |
| 不眠で眠れない | マイレストS / ドリエル / ドリエルEX | 3 件すべてがジフェンヒドラミン塩酸塩の単剤 |
| 生理痛がひどい | イブメルト / 命の母ホワイト《パウチ》 / 同《瓶》 | 同一製品の包装違い。11 成分すべて一致 |
| 花粉症で目がかゆい | アイブルー抗菌目薬α / マリンアイ抗菌S / アイエースVクール | 上位 2 件は組成が完全同一（4 成分） |
| 咳と痰が出る | 新スカイブブロンゴールド微粒 / バファリンかぜEX錠 / 同ゴールド錠 | ジヒドロコデインリン酸塩、dl−メチルエフェドリン塩酸塩、無水カフェイン ほか |
| のどが痛くて熱がある | 新スカイブブロンゴールド微粒 / バファリンかぜEX錠 / ジキニンドライシロップ | ジヒドロコデインリン酸塩、dl−メチルエフェドリン塩酸塩、アセトアミノフェン |

| 胸やけがする | ソルマックEX2 / ストーゼ胃腸内服液 / 救胆 | カルニチン塩化物、ソウジュツ流エキス |
| くしゃみと鼻水が止まらない | バファリンかぜEX錠 / 新スカイブブロンゴールド微粒 / モリゼンチトウ | ジヒドロコデインリン酸塩、dl−メチルエフェドリン塩酸塩、無水カフェイン |

影響
: 「3 つの選択肢から選ぶ」という提示でありながら、実質的に同じ薬効成分の製品が並びます。利用者が「効かないので別のものを」と 2 つ目を追加で服用した場合、同一成分の重複服用になります。麻薬性鎮咳成分とカフェインの重複は過量摂取のリスクを伴います。
修正案

### I11中同名製品の重複行と、成分が空の行

検証

カロナールA 行1: 種類=解熱鎮痛薬 成分='アセトアミノフェン' 行2: 種類=第2類医薬品 成分=''（空） ← 推奨に出ているのはこちら クミアイ新頭痛錠 行1: 成分='アセトアミノフェン / エテンザミド / 無水カフェイン' 行2: 成分='アセトアミノフェン / 無水カフェイン' ← エテンザミドが欠落

### I9中ピコスルファートがビサコジルの別名として登録されている

場所
: `recommendation_constants.py:257-261`。`RISK_INGREDIENTS_EXCLUDE["ビサコジル"]["aliases"]` に `"ピコスルファート"` が含まれます。
問題
: ピコスルファートナトリウムはビサコジルとは別の化合物です。どちらも刺激性下剤ですが、ピコスルファートは腸内細菌により活性化されるプロドラッグで、作用部位と特性が異なります。別名として登録されているため、ピコスルファート含有製品に「ビサコジルが含まれています。妊娠中・授乳中、15 歳未満の方は使用前に医師にご相談ください」という、含まれていない成分を名指しする警告文が出ます。
修正案
: 独立したエントリに分離する。クラスとして束ねたい場合は `IRRITANT_LAXATIVE_INGREDIENTS`（同ファイルに既存）を使い、警告文は成分ごとに持つ。

## 8. 推奨する対応順

前回のスコアリング精査（23 件）は `docs/planning/改善方針_2026-09.md` でロードマップに割り当て済みと理解しています。本レポートの 13 件をそこに接続する形で提案します。

1. 即時（数行、安全に直結）

- I3：`ingredient_diversity.py` の `extract_main_ingredients` 呼び出しに `max_count` を明示。10 箇所の引数追加のみで、上位 3 件の成分重複が大きく改善します。
- I2：成分辞書の `NSAID` エントリを外すか、重複判定を `category` ベースに変更。最も重い警告が復活します。
- I6：成分名比較前の NFKC 正規化。前回の H8（医薬品の種類の括弧）と同じ修正方針にまとめられます。
- I9：ピコスルファートを独立エントリに分離。
- I11：成分が空の行を候補から除外。
2. 短期

- I1：底上げを `max(base_score, 下限)` に変更。前回の H6（スコア飽和）と同一箇所の修正であり、まとめて着手し、スナップショットテストで前後比較すべきです。この 1 箇所の修正で、成分評価を含む重み付けモデル全体が初めて順位に効くようになります。
- I5：相互作用判定の 2 関数を統合し、警告文を要約に置き換え。
- I7・I8：接尾辞の一般化、クラス名対応、型ガード。
3. 中期（データ整備）

- I4：相互作用マスタの名称を一般名に統一し、商品名を同義語として保持。
- I10：成分集合の重なり率による一般規則の導入。
- I12：`医薬品の種類` 列の分割。スコアリング規則の前提に関わるため、影響範囲が広く、回帰網の整備後に着手すべきです。

副作用・相互作用マスタの拡充（現状 275 行・185 行）は継続的な作業になります。ただし I1 を直さない限り、マスタを拡充しても最終スコアには反映されません。順序としては I1 を先に処置することを強く勧めます。
