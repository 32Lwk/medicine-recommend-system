# バーチャルヒューマン対話機能の実現可能性

 チャット型医薬品相談ツールに「バーチャルヒューマンとオンラインで対話する」機能を載せる場合の、 既存資産・技術選択肢・レイテンシ・法規制・コストの調査結果と、段階導入案。 

 調査日 2026-09-14 対象コミット 40c8a1f 対象 Web（FastAPI + 素の JS）／ LINE 状態 調査のみ・コード変更なし 

## 00結論

1. すでに 7 割できている。 音声入力（Web Speech API）、サーバー TTS（Polly / Google Cloud TTS、SSML 付き）、SSE ストリーミング、処理段階の日本語ラベル、「Sage」というキャラクター名と世界観 — バーチャルヒューマンの部品はほぼ揃っている。欠けているのは顔とターン制御の二つだけ。
2. ただし本当の障壁は見た目ではなくレイテンシ。 症状推奨の実測は p95 ≈ 24 秒。人が「会話」と感じる上限はおよそ 1 秒。ここを設計せずにアバターを載せると、24 秒間ただ黙って立っている人形になり、体感品質はテキスト UI より悪化する。
3. 法規制上、AI アバターは薬剤師の代替にならない。 2026 年 5 月 1 日施行の改正薬機法では、要指導医薬品のオンライン販売は「薬剤師がビデオ通話等で情報提供・指導した場合」に限られる。人型が喋るビデオ通話風 UI は、この「遠隔服薬指導」との誤認を招きやすい — 本件で最大の法務論点。
4. 写実的（フォトリアル）より様式化されたキャラクターが有利。 医療文脈の研究では、ディープフェイク調の写実アバターは不気味の谷に落ちて信頼を下げ、カートゥーン調の人型は「親しみやすく不気味でない」と評価される報告がある。既存の Sage をそのまま立体化するのが最も筋が良い。
5. 推奨は 3 段階。 Phase 1 は外部依存ゼロ・追加コストゼロの自前 2D アバター＋既存 TTS。Phase 2 で雑談・問診レーンだけを低遅延音声化。Phase 3 は店頭キオスク等の必要が出たときだけ外部ベンダー。推奨ロジックは何段階目でも音声 LLM に渡さない（ルールベース維持という既存の設計思想と一致）。

この報告書の限界

ベンダーの遅延・価格は 2026 年 9 月時点の公表値および比較記事に基づく概算で、各社の測定定義はバラバラ（「サーバー側生成のみ」と「マイクから口が動くまで」が同じ表で並んでいる）。採用前に必ず一次情報と PoC で確認すること。法規制部分も実務判断ではなく、薬事の専門家への確認が必要。

コードを読んで分かった要注意点

## 02「バーチャルヒューマン」の三つの解釈

この言葉は少なくとも三つの別物を指す。どれを指しているかで、実装量もコストも法務論点も変わる。

価格は 2026 年 9 月時点の公表値・比較記事ベースの概算。

| | 方式 A 自前描画型 | 方式 B 対話アバター API | 方式 C 事前生成動画 |
| --- | --- | --- | --- |
| 中身 | 2D / 3D キャラクターをブラウザで描画。音声は既存 TTS、口形はそれに同期 | WebRTC で人物映像がリアルタイムに降ってくる | 定型の説明・注意喚起を動画として作り置き |
| 代表 | Live2D Cubism、VRM（@pixiv/three-vrm）、TalkingHead.js | HeyGen LiveAvatar、Tavus、Simli、Anam、bitHuman、Azure TTS Avatar | HeyGen Avatar IV、Synthesia |
| 追加遅延 | ほぼゼロ（TTS の遅延のみ） | 公称 300–1000 ms | — リアルタイム性なし |
| 追加コスト | ゼロ ライセンス除き従量課金なし | $0.10–0.37 / 分 | 制作都度 |
| 日本語 | 問題なし（既存 TTS のまま） | 各社対応を謳うが口形の自然さは要検証 | 問題なし |
| 相談内容の外部送信 | 増えない | 増える 症状・服薬情報が新たな委託先へ | 増えない |

方式 C は「バーチャルヒューマンとの対話」ではないが、用法・用量の説明や受診勧奨といった定型部分を動画化する使い方は、安全性の観点でむしろ有望（毎回 LLM に喋らせるより内容が固定されるため）。対話機能とは別に検討する価値がある。

## 03本丸はレイテンシ

この機能の成否を分けるのは、キャラクターの出来ではなく沈黙の長さ。テキストチャットは待たされても「処理中」と分かるが、人型が黙って立っていると故障に見える。

 症状推奨レーンの実測値は docs/dev/PHYSICAL_SYMPTOM_E2E.md:95（YAML physical 10 件で p95 約 24 秒、KPI は 15 秒未満）。「対話の目安」はリアルタイムアバター各社が sub-1s を訴求水準に置いていることから採った目標線。同じ尺度で並べると、両者は詰められる差ではなく桁が違うことが分かる。 

### だから、レーンを分ける

全部を速くするのは無理だが、全部が遅いわけでもない。既存の IntentRouter はすでに雑談・コンシェルジュ・症状推奨を振り分けている。アバターの発話設計もこの境界に合わせるのが自然。

- 速いレーン（挨拶・雑談・アプリの使い方・問診の聞き返し）— ここは短い LLM 応答なので、音声対話として成立する余地がある。
- 遅いレーン（症状からの OTC 推奨）— ルールベース採点＋LLM 説明で 20 秒超。速くするのではなく、沈黙を埋める設計にする。

既存資産がそのまま使える

src/services/processing_user_labels.py は、フロー × ステップごとの日本語ラベル（「いま何をしているか」）をすでに持っていて、SSE で段階的にフロントへ流れている。これを繋ぎ発話の台本としてそのまま TTS に回せば、24 秒の沈黙が「症状を確認しています」「候補を絞り込んでいます」という自然な間になる。新しく作るものはほぼ無い。

 緑の経路が今回の提案の中身。推奨パイプラインが走っている 24 秒間、既存の processing_status 段階イベントを繋ぎ発話として TTS に回し、アバターに喋らせる。上段の本回答経路は現状のまま。この一本の経路を足すかどうかで、アバターが「考えている人」に見えるか「固まった人形」に見えるかが決まる。

## 06法規制と「誤認」という最大のリスク

2026 年 5 月 1 日施行の改正薬機法により、要指導医薬品のオンライン販売は「薬剤師がビデオ通話等を通じて適切な情報提供・指導を行った場合」に限って可能となった（改正薬機法第 29 条の 5〜9）。電話・メール・チャットでは販売できない。

ここに本件の危険がある。 人型が画面に現れて音声で応答する UI は、利用者から見て「ビデオ通話による服薬指導」と区別がつきにくい。AI アバターは薬剤師でも登録販売者でもなく、この要件を満たさない。現行アプリが慎重に避けてきた「診断しない」という一線に加えて、「専門家による遠隔指導を受けている」と誤認させないという新しい一線が必要になる。

### 設計上の必須要件

- アバターに白衣・薬剤師バッジ・調剤台などの職業記号を与えない。キャラクターが専門資格者に見える表現は避ける。
- 画面上に常時「AI であり、薬剤師・登録販売者ではない」旨を表示する。会話の冒頭でアバター自身にも名乗らせる。
- 「薬剤師さんですか」「これで買えますか」等の問いに対する固定応答を用意する（LLM の自由生成に委ねない）。既存の Concierge テンプレート機構で実装できる。
- 指定濫用防止医薬品 8 成分（エフェドリン、コデイン、ジヒドロコデイン、ジフェンヒドラミン、デキストロメトルファン、プソイドエフェドリン、ブロモバレリル尿素、メチルエフェドリン）に関する会話では、18 歳未満販売禁止・本人確認義務の存在に触れる。アバターが親しみやすいほど、この種の注意喚起が流れやすくなる点に注意。
- 緊急度の高い症状での受診勧奨は、アバターの演出で和らげない。既存の store_emergency_handler の判定結果を、声のトーンで薄めない設計にする。

### その他の法務論点

| 論点 | 内容 |
| --- | --- |
| 肖像・実在人物 | 実在の人物をモデルにする場合は肖像権・パブリシティ権の許諾。声優を起用する場合は AI 利用範囲を明記した契約が必要 |
| プライバシーポリシー改定 | 現行ポリシー（2026-06-22 改定）は音声・映像データの取得を想定していない。音声を録音・外部送信するなら改定が必須 |
| カメラ利用 | 利用者の顔を撮る設計にすると、取得情報の性質が大きく変わる。特段の理由がなければカメラは使わないことを推奨 |
| 外部委託先の追加 | 方式 B は症状・服薬情報が新たな海外事業者へ渡る。第三者提供・越境移転の整理が必要 |
| ライセンス | 本リポジトリは PolyForm Noncommercial。商用アバター SDK との組み合わせは、商用化時のライセンス見直しと併せて検討 |

## 07見た目の設計根拠

「どこまで人間に似せるか」は好みの問題に見えて、医療文脈では実証研究のある論点。写実に寄せるほど良い、ではない。

- ディープフェイク技術で生成された写実的なエージェントは「幽霊のような」印象を与え、不気味さを引き起こしたという報告がある。不気味の谷に落ちた表現は信頼を下げ、視線を逸らさせ、ラポールを損なう。
- 対照的に、カートゥーン調で動きを抑えた人型エージェントは「親しみやすく、効果的で、不気味でない」と評価された。
- 一方で、仮想医療エージェント全般は患者から信頼され受容される傾向があり、擬人化の度合いは利用者の感情反応や個人的な情報を進んで話すかどうかに影響する。症状相談という用途では、この「話しやすさ」は実利がある。
- Mayo Clinic では 2025 年に外科医の外見を再現したアバター（HeyGen IV）による術後教育のパイロット研究が行われており、写実路線にも実績はある。ただしこれは実在する担当医の再現であって、匿名の AI 人格とは前提が異なる。

結論

既存の「Sage」を様式化されたキャラクターとして立体化するのが、エビデンスとも法規制（職業記号を避ける）とも、既存のブランド資産とも整合する。写実的な人物アバターは、信頼を上げるどころか下げる可能性があり、かつ薬剤師誤認リスクを最大化するため、本件では推奨しない。

アクセシビリティも要件に含める。既存 UI は読み上げ・文字サイズ・多言語に配慮しており、高齢者・過疎地の利用者を主要な想定利用者に置いている（AWS 地域創生コンテスト向け調査より）。アバターは常に無効化できること、音声なしでも全機能が使えること、字幕を必ず併記することを前提にする。

#### 顔をつける — 外部依存ゼロ・追加コストゼロ

既存の TTS と SSE の上に、2D / VRM キャラクターと口形同期を載せるだけ。新しい外部サービスも従量課金も発生しない。

- /api/tts を文単位の逐次合成・逐次再生に変更（体感遅延の主因）
- 音量ベースのリップシンク＋簡単な表情（待機・傾聴・発話）
- processing_status の段階ラベルを繋ぎ発話として音声化
- アバター ON / OFF トグルと字幕の常時併記

#### 会話にする — 速いレーンだけ低遅延音声化

挨拶・雑談・アプリ説明・問診の聞き返しに限って gpt-realtime-mini を使い、割り込み可能な音声対話にする。

- IntentRouter が「速いレーン」と判定した場合のみ Realtime セッションを開く
- 症状推奨に入った時点で Realtime を閉じ、既存のルールベース経路へ戻す
- プライバシーポリシー改定と、音声データの保持方針の明文化を先に済ませる

#### 必要になったら — 外部ベンダー

店頭キオスクや自治体窓口など、写実的な人物像が要件になる場面が出たときだけ検討する。LiveKit Agents の抽象化層を挟み、bitHuman のようなローカル実行可能な選択肢を優先的に評価。

全段階を通じた不変条件

OTC の推奨ロジックは、どの段階でも音声 LLM に渡さない。 候補選定はルールベース採点のまま、LLM は説明文の生成に留める — これは既存アプリの設計思想であり、薬名の自由創作を防ぐ安全装置そのもの。アバターは出力の提示層であって、判断層に入れてはいけない。

## 11確認したいこと

ここから先の設計は、次の回答によって大きく変わる。 Q1〜Q4 は特に、推奨する方式そのものが変わる項目。

1. 「バーチャルヒューマン」はどの見た目を想定しているか様式化されたキャラクター（Sage の立体化）／ 写実的な人物 ／ まだ決めていない。第 02 節・第 07 節の判断が変わる。
2. 音声で会話する必要があるか、それとも「顔のある読み上げ」で足りるか前者はターン制御・割り込みの実装が必要で難度が跳ね上がる。後者なら Phase 1 だけで完成する。
3. 主目的はどれかコンテスト・発表でのデモ ／ β 利用者の体験改善 ／ 商用化に向けた差別化 ／ 店頭キオスク等の新チャネル。許容できるコストと作り込みの深さが変わる。
4. 月額でいくらまで許容できるか既存の OpenAI 予算ガードと同じ枠内か、別枠か。方式 B は月 1,000 セッションで 4.5 万〜16.7 万円規模になる。
5. 対象チャネルは Web だけか LINE は Messaging API の制約上、リアルタイム音声対話ができない。Web 限定で良いか、LINE でも何らかの形が要るか。
6. 利用者のカメラを使う想定はあるか表情に反応させる等。使わない前提で良ければ、プライバシー面の論点が大幅に減る。
7. キャラクターの制作リソースはあるかイラスト・3D モデルの外注予算、または VRoid 等での自作。既存の Sage にビジュアル資産はあるか。
8. 声はどうするか現行の Google / Polly の合成音声を継続するか、キャラクター性のある音声（にじボイス・CoeFont 等）に変えるか。
9. 着手の時期・期限はあるかコンテストや発表の予定に紐づくなら、Phase 1 に絞って確実に仕上げる判断があり得る。
10. 薬事の専門家に相談できる体制はあるか第 06 節の誤認リスクは、実装前に専門家の確認を取っておきたい種類の論点。
