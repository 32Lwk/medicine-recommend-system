# 推奨スコアリング精査レポート

 対象コミット 40c8a1f（main） 実施日 2026-09-14 対象範囲 約 13,800 行（rule_based_recommendation / candidate_scoring / scoring_utils / final_score_calculator / ingredient_diversity / recommendation_finalizer / score_calculators） 

安全性に関わる指摘が 1 件あります（H1）。年齢制限欄の最小年齢抽出が「1回量」の `1` を年齢として拾うため、 10 歳のユーザーに「15才未満：服用しないこと」の解熱鎮痛薬が推奨されます（実測で再現）。CSV 7,495 行のうち 1,941 行が同じ過小抽出の対象です。他の指摘に優先して確認されることを勧めます。

結論。スコアリングは「候補に点を付けて上位 3 件を選ぶ」という役割を、現状ほとんど果たしていません。主要な入力（頭痛・発熱・のど痛・鼻炎・風邪症状）では 16〜22 製品が同一の最大値 `1.3629` で並び、区別できるスコアが 5〜11 種類しかありません。上位 3 件は実質的に CSV の並び順と、後段の製品名ベースの規則で決まっています。

原因は単一の不具合ではなく、入力側（効能テキストの解析）と出力側（スコアの合成）の両方にあります。効能効果の解析は 3 つの独立した欠陥で CSV の 29〜36% の行に対して誤判定し、スコア合成は底上げと上限の組み合わせで大半の候補を同じ値に潰しています。

加えて、特定の成分表記で推奨処理全体が例外停止する不具合（H2、本番ログに発生実績あり）と、最終安全フィルタの除外が無条件に取り消される不具合（H7）を確認しました。

既存テスト 121 件は Docker（Python 3.11）で全て通過します。 121 passed ただし本レポートの指摘はいずれも検出されていません。理由は「7. テストの実効性」に記載します。

7. 相対・表示スコア L1575-1633、score_calculators L101-120 `relative_score = final / max`、`display_score = (min(raw,1)×100 − (順位−1)×1.5) × (1 − 不足情報減点)`。不足情報減点は最大 0.15 で final_score には反映しない。

### 最終スコアの式（final_score_calculator.py L1367-2001）

base_score = 0.30·symptom + 0.20·efficacy + 0.12·age + 0.03·usage + 0.10·side_effect(≤0) + 0.05·interaction(≤0) adjusted = 0.55 … 主要解熱鎮痛薬で base < 0.55 （L1951-1954） = 0.50 … それ以外で base < 0.45 （L1962-1966） = 0.50 + (base−0.45)×10 … 0.45 ≤ base < 0.50 （L1967-1970 ← H6b） = base … base ≥ 0.50 expanded = 0.5 + ((adjusted−0.5)/0.23)^0.85 × 0.23 （adjusted ≥ 0.5 のとき） scaled_adj = clamp(adjustment_score, −0.30, 上限) 上限 = 0.80 主要解熱鎮痛薬 / 0.40 総合感冒薬 / 0.30 解熱鎮痛薬・外用薬（のど） / 0.25 その他 raw_score = expanded + scaled_adj （クリップなし。1.0 を超える） 例: 主要解熱鎮痛薬と判定された製品は base によらず adjusted=0.55 → expanded=0.5629、 adjustment_score ≥ 0.80 なら raw_score = 0.5629 + 0.80 = 1.3629（実測の最大値と一致）

この構造のため、順位は「どの上限区分に入るか」と「base が 0.55 未満か」でほぼ決まり、定数表（`SYMPTOM_PATTERN_OPTIMIZATION` 等）の細かなボーナス値は最終順位にほとんど寄与しません。

### H1高・安全年齢制限の誤読により、成人専用薬が小児に推奨される

場所
: `_extract_min_age_value`（candidate_scoring.py:228-248）が年齢制限文字列から `(\d+)` の最初の数字を最小年齢として採用する。前段の正規化（L847）は `re.search(r'(\d+)歳', …)` で「歳」表記のみを対象とするため、「才」表記の行では書き換えが起きない。
再現
: 年齢制限欄が `[年齢:1回量] 成人(15才以上):3錠 15才未満:服用しないこと` の製品で:

_extract_min_age_value(...) → 1 ← 「1回量」の 1 を最小年齢として採用 re.findall(r'(\d+)', ...) → ['1', '15', '3', '15'] re.search(r'(\d+)歳', ...) → None ← 「才」表記のため L847 の書き換えが発火しない calculate_age_fit_score(age= 5) = 0.8 calculate_age_fit_score(age=10) = 0.8 ← 「適合」と評価される calculate_age_fit_score(age=14) = 0.8

通しで実行すると、 10 歳・「のどが痛い」で `イブスリーショットプレミアム`（年齢制限「15才未満：服用しないこと」）が 2 位に推奨されます（score 1.3629）。
規模
: 年齢制限が非空かつ年齢表記を含む 2,675 行のうち、抽出した最小年齢が本文中の最小年齢と食い違う行が 2,175 行。内訳は過小抽出 1,941 行（実際より緩く判定＝危険側）、過大抽出 234 行（服用可能な小児を候補から落とす）、一致 500 行。年齢制限が「才」のみで「歳」を含まない行は 1,218 行。
補足
: 実測では 5 歳・「頭痛がする」は 0 件（別のガードが作動）でしたが、10 歳では通過しました。`age_policy.parse_min_age_years` も同じ先頭一致方式のため、同様の確認が必要です。
修正案
: 年齢制限文字列から `(\d+)\s*[歳才](?:以上|~|〜|から)` の形で「服用可能な下限」を全て抽出し、その最小値を採る。「服用しないでください/服用しないこと」を伴う年齢は上限側として別に扱う。CSV 全行を通して抽出結果を検証するテストを併せて追加する。

### H3高効能効果テキストの解析に 3 つの独立した欠陥

症状と効能の照合は推奨の中核ですが、テキスト分割と単語境界判定に 3 つの別々の不具合があり、実データの大きな割合で誤判定します。

(a)
: 「・」で分割しない（candidate_scoring.py:1367 `re.split(r'[、。，．,.]', …)`）。効能 `頭痛・発熱` は 1 パート `頭痛発熱` となり、単語境界判定で「頭痛」が見つからない。

calculate_symptom_match_score([頭痛], 風邪薬, 効能'頭痛・発熱') = 0.0 calculate_symptom_match_score([頭痛], 風邪薬, 効能'頭痛、発熱') = 0.85

効能効果に「・」を含む行は 2,735 行（36%）、うち「、」を一切含まない行は 2,202 行（29%）。これらは症状適合度が 0 になり得ます。なお `calculate_efficacy_specificity_score` 側は `len(part) > 10` のときだけ「・」で分割するため、2 つの関数で挙動が食い違っています。
(b)
: 接続詞の正規表現が文字クラスになっている（scoring_utils.py:506 `re.split(r'[及び並びにまたは又は]', part)`）。意図は「及び」「並びに」「または」「又は」での分割ですが、実際は 1 文字ずつで分割されます。

re.split(r'[及び並びにまたは又は]', 'めまい又は頭痛及びたん、はきけ') → ['め', 'い', '', '頭痛', '', '', 'ん、', 'きけ'] E(めまい, 効能'めまい又は頭痛') = 0.0 E(めまい, 効能'めまい、頭痛') = 0.1649

「に」「は」「た」「ま」「び」を含むあらゆる症状語（たん、はきけ、鼻づまり、めまい など）が破壊されます。該当する効能を持つ行は 715 行（10%）。
(c)
: 句読点の除去で漢字が連結し、単語境界判定が失敗する。`normalize_text`（scoring_utils.py:86-97）が句読点を削るため `頭痛、発熱` が `頭痛発熱` になり、「頭痛」の直後が漢字「発」であるため境界条件を満たさない。

has_symptom_in_efficacy(効能'頭痛、発熱', ['頭痛']) = False has_symptom_in_efficacy(効能'腰痛・肩こり', ['腰痛']) = False has_symptom_in_efficacy(効能'肩こり・腰痛', ['腰痛']) = True ← 語順で結果が変わる has_symptom_in_efficacy(効能'頭痛', ['頭痛']) = True

この関数は「効能に症状が明記されているか」の判定に広く使われており、効能特異性の 0.5 底上げ（scoring_utils.py:741-763）が発火せず、さらに `filter_by_efficacy_symptom_match`（candidate_scoring.py:618-631）では適切な候補が誤って除外されます。
修正案
: 分割記号を 2 つの関数で共通化し（「・」「／」「/」を含める）、接続詞は `re.split(r'及び|並びに|または|又は', …)` と交替で書く。単語境界判定は句読点を削る前のテキストに対して行うか、句読点を区切り記号（空白等）に置換する。

### H6高スコアが上限で飽和し、順位を決める情報量がない

実測
: | 入力 | 詳細採点数 | 最大値 | 最大値と同点 | 異なる値の数 |
| --- | --- | --- | --- | --- |
| 頭痛がする | 54 | 1.3629 | 21 | 6 |
| 熱がある | 44 | 1.3629 | 22 | 5 |
| のどが痛くて熱がある | 489 | 1.3629 | 18 | 6 |

| 咳と痰が出る | 500 | 1.3629 | 4 | 4 |

| 便秘がつらい | 27 | 0.500 | 9 | 4 |
| 不眠で眠れない | 42 | 0.550 | 4 | 2 |

「頭痛」では カロナールA（`adjustment_score` 2.0）と スカイブブロンファースト（1.1）が同点 1.3629 で、出力順は前者が 3 位、後者が 1 位。表示スコア 85.0 / 83.7 / 82.5 は順位のみから決まっています。
原因

(b) 非単調な補間（L1967-1970）：`adjusted = 0.5 + (base − 0.45) × 0.5 / 0.05` は `(base − 0.45) × 10` であり、base 0.47 → 0.70、0.499 → 0.99 と急伸する一方、base 0.50 ちょうどは 0.50 のまま。コメントの「最大 0.73」も破られます。L1959 の主要解熱鎮痛薬向け補間 `(base−0.55)×0.05/0.05` は恒等式で、意図した式になっていません。

(c) 表示への影響：`calculate_display_score_absolute` は `min(raw, 1.0)` で丸めるため、raw ≥ 1.0 の候補は全て「100 − 順位補正」になり、ユーザーに見える「最適度」は順位以外の情報を持ちません。
修正案
: 短期：L1970 の係数を 0.5〜0.55 への線形補間に直し、上限超過分を小さい係数で残す（例 `上限 + 0.1 × (adj − 上限)`）だけでも同点は解消します。中期：base の底上げを廃止し、成分・種類の優先度を base の重みに統合します。

### M11中 strict モードでリスク重みの符号が反転する（潜在）

内容

修正案
: strict モードは重みの絶対値を大きくする実装に直し、コールスタック検査は削除する。
