## 2. 規制トレンド（2026-05-01 施行中心）

### 2.1 要指導医薬品のオンライン化

- 薬剤師が**ビデオ通話等**で情報提供・指導し適切と判断した場合に特定販売可。
- **特定要指導医薬品**は対面必須のまま。

### 2.2 指定濫用防止医薬品

- 旧「濫用等のおそれのある医薬品」が法令位置づけ強化。
- 年齢・氏名（18 歳未満）・他店購入・複数購入理由などの確認。
- 18 歳未満への複数・大容量は販売禁止。オンライン確認要件あり。

**本アプリへの意味**:
- AI チャットは**販売行為そのものではない**が、「買えるように誘導する UI」「診断したように見える顔 UI」は規制文脈で危険。
- 濫用該当成分の推奨カードは、年齢未確認のまま出しすぎない情報設計が必須（既存 doping/age フラグと接続）。
- VH（人の顔）は遠隔服薬指導と誤認されうる — 改善ロードマップ R3 と同じ結論。

出典例: 厚労省 PDF、東京都・山口県・富山県の改正案内ページ。

## 3. 競合・代替ポジション

| 類型 | 例 | 強み | 本アプリとの差 |
|------|-----|------|----------------|
| 有人薬局アプリ | アイン「安心お薬サポート」 | 実薬剤師、お薬手帳連携、会員前提 | 本アプリの「薬剤師要請」はデモ。誤認リスク大 |
| AI OTC 相談 | キュアベル お薬相談チャットボット | 独自 DB 明示、ヒアリング×提案 | 類似。差別化は Red Flag・危機検知・ルールベース透明性 |
| 調剤 LINE | つながる薬局 等 | 処方箋送信・待ち時間短縮・大規模 | 用途が違う。OTC 相談はニッチ |
| 汎用 LLM | ChatGPT 等 | 速い・無料感 | ハルシネーション。本アプリのルールベースは対抗軸 |
| 店頭スタッフ | DRUG 店舗 | 信頼・在庫・販売完結 | キオスク連携は将来。今は緊急文言フラグのみ |

**ポジション仮説（採用）**:  
「**診断しない / 売らない / ルールで選ぶ / 危ないときは止める**」情報補助。UX は診断クリニックや有人薬局アプリを真似しない。

## 4. チャネル戦略（市場慣行）

### LINE（薬局領域）
- 友だち追加 → あいさつ → リッチメニュー → 処方箋/問診/通知が定石。
- 高齢者向けは**短い説明・大きいボタン・店頭 QR**。
- 医療情報配信は薬機・景表・同意が必要。

### Web チャット
- AI Chat UI の信頼は **ストリーミングと状態説明**で稼ぐ（待ちを隠さない）。
- 日本向け「subtle UX / 信頼の静けさ」トレンド（2026 デザイン論）。派手さより依存可能性。

### 匿名 vs ログイン
- ヘルスケアは**入口匿名＋価値後の任意登録**が離脱を抑える。
- 薬局アプリの会員必須は「かかりつけ・調剤履歴」があるから成立。本アプリに同じ強制は不適。

## 6. UX ベンチマーク示唆（外部）

1. 待ち: time-filler は有効だが、**実遅延の代替ではない**。
2. 信頼: 出典・FDA 的検証・過度な擬人化の抑制。
3. 高齢: デジタル庁 a11y、ヘルスリテラシー格差。
4. OTC デジタル態度: eHealth literacy が受容を左右（PMC 研究）。

## 9. NotebookLM deep/fast からの 10 要点（上司注付き）

Notebook 照会の要約。**米ドル市場予測や「必ずビデオ通話を自社に組め」は販売事業者向け示唆であり、本アプリ（非販売・情報提供）への直訳は禁止。**

1. 高齢化・セルフケア需要 → 高齢 UX と Quiet UX が本丸  
2. OTC EC 拡大 → 「買う前の相談」ニッチは有効だが販売 UI は作らない  
3. セルフメディケーション税制は認知不足 → 今はコア機能にしない  
4. 受診と OTC の見極めガイド → 既存 Red Flag と一致（強化せよ）  
5. 要指導オンラインは**薬剤師ビデオ前提** → AI 顔は誤認リスク  
6. 特定要指導は対面維持 → UI で「買える」と誤解させるな  
7. 指定濫用防止の確認義務 → 年齢未確認の推奨出し過ぎ禁止  
8. 症状検索が最上流（ユビー等） → 病名ではなく症状入口は正しい  
9. Quiet UX / 根拠明示 → Sage の静かな信頼と整合  
10. アドヒアランス・PHR → 90 日 Won't（スコープ膨張）
