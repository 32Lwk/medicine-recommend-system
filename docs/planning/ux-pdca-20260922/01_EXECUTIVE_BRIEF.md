# 01 Executive Brief — 上司承認用（1ページ）

**日付**: 2026-09-22  
**結論**: UX 投資は「見た目の刷新」ではなく、**(1) 安全のチャネル対称、(2) 待ち時間の実測短縮＋誠実な進捗、(3) 継続IDの段階設計、(4) 信頼導線の情報設計**に集中せよ。会員登録・VH・全面リデザインは今は Won't。

---

## いま起きていること（診断）

- **エンジンは強いが、本番ユーザーに届く UX 補正の多くが OFF**（`_ux_rollout_flag` 本番未設定=OFF）。「改善したつもり」と「改善が届いた」が乖離。
- **最大の体感負債は待ち時間**（Physical p95 ≈24s。KPI 15s、旧計画 5s は未達）。進捗 UI はあるが、入力ロックと説明不足で「壊れた」に読まれる。
- **チャネル非対称が安全問題**（LINE の pending 削除には medical/crisis cancel あり、Web に無い）。handoff トークンはプロセス内メモリでマルチインスタンス耐性なし。
- **「ユーザー情報登録」は会員ではない**のに文言がアカウント誤解を誘発。Web 単独に長期 ID がなく、LINE だけ継続性が強い。
- **見た目（Sage Terrace）は既に方向 B で定着**。プロト増産は移植負債を増やすだけ。

---

## 市場からの制約（要約）

| 事実 | UX への意味 |
|------|-------------|
| OTC 市場は定義差で約 0.7〜1.3 兆円。2025 は物価高で前年割れ指摘も | 「市場が伸びるから急げ」は過信。差別化は安全性と信頼 |
| 2026-05-01 薬機法: 要指導のオンライン＋指定濫用防止の厳格化 | AI 顔・診断っぽい UI は遠隔服薬指導と誤認リスク。濫用成分の安易な推奨 UI は禁止領域 |
| 競合: 薬局アプリは**有人薬剤師**、AI 相談は**DB 明示**が売り | 本アプリの勝ち筋は「ルールベース選定の透明性＋Red Flag」。有人接続デモの誤認は致命傷 |
| 薬局 LINE は処方箋・待ち時間短縮が主戦場 | 本 LINE は OTC 相談特化。parity 全合わせは無駄。handoff 品質が本丸 |

## 承認する方針（Must）

1. **W0（2週間）**: Web pending medical cancel を LINE 同等に。`SAFETY_EMERGENCY_CHANNEL_SPLIT` 本番方針決定。handoff 失効 UX 明示。
2. **W1（30日）**: 待ち時間 — `LATENCY_*` の段階本番化 **または** 候補上限で p95&lt;15s を先に取る。待ち UX は 3s/8s/15s の段階説明＋早期キャンセル。
3. **W2（45日）**: 「登録」文言の再定義（任意プロフィール）。同意のサーバ記録。**会員は作らない**。LINE Login は任意オプションとして設計文書のみ。
4. **W3（60日）**: サイト UX — 信頼ストリップ／ウィザード進捗／トリアージ入口（プロト 36/39/44）の**選択移植のみ**。About 一般向け入口 1 画面。
5. **計測**: Emergency FP 後再入場、handoff 成功率、属性完了率、p95、離脱（送信後無操作）をダッシュボード化。

## 明示的 Won't（90日）

- メール会員・パスワード必須
- バーチャルヒューマン本番
- UI 方向 C 全面、プロト全移植
- SafetyGate 弱体化による FP「改善」
- キオスク専用 UI（文言フラグ方針が固まるまで）

## 成功の定義（90日）

- Web/LINE の安全 SessionOps 対称（テスト付き）
- Physical p95 &lt;15s（または公式に KPI 改定＋合意）
- 「登録」誤解率の定性ヒアで改善（専門家β 5 名以上）
- handoff 成功率が測定可能で、失敗時に再発行導線がある
