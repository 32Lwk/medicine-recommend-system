## 2. 追加すべき点（検討推奨）

### 高優先度
- **デモ動画**: ⑤で「2～3分のデモ動画を用意」と記載済み。提出前に必ず作成し、提出資料または二次審査で提示すること。
- **gantt_chart.png**: ④(6) で `gantt_chart.png` を参照している。ファイルが `docs/archive/mitou/docs/` に存在するか確認すること。

### 中優先度
- **② 修了後のアクション**: 竹内PM「プロジェクト修了後、どういうアクションを考えているか」を簡潔に記述。現状「未踏アドバンスト等も視野に」はあるが、もう1文あるとより明確。
- **③ 既存研究・ツールの具体名**: 時間があれば、医薬品推奨・OTC相談関連の論文・システム（例: キーワード検索でヒットする既存製品）を1～2件挙げ、「それらと本提案の違い」を1文で書くと斬新さが伝わりやすい。調査不足で書くと逆効果のため、確実なもののみ。

### 低優先度
- **phase1 の「任せたら途中で投げない」**: ⑤や⑧に人柄が伝わる一言を入れたい場合、phase1_answers のこの表現を参考に短文で追記可能。
- **セキュリティ・キャンプ2026コネクト**: phase2 合意で「記載しない」方針。必須ではないが、参加予定であれば⑤の「その他」に追記すると腕前の補足になる。

## 3. 不明点・確認すべき点

### 内容面
1. **生年月日・年齢の確認**: phase1 では 2005/10/28、⑥では「2026年4月1日時点で満20歳」→ 2005年10月生まれであれば 2026年4月1日時点で満20歳（5月で20歳になる）で正しい。
2. **指導教員**: 理学部2年で研究室未所属は一般的。⑥で「指導教員はいない」と記載済み。問題なし。
3. **アルバイトとの両立**: 「プロジェクト開発を優先する時間を確保する」とあるが、週30時間開発＋学業＋アルバイトの具体的な配分（例: アルバイトは週○時間程度に調整予定）があると、計画のリアリティが伝わる。書かなくても応募要件違反ではない。

### 技術面
4. **図ファイルのパス**: `../../LaTex/photo/system.png` 等は `docs/archive/mitou/docs/` からの相対パス。ビルド時のカレントディレクトリが `docs/archive/mitou/docs/` であれば正しい。gantt_chart.png は同ディレクトリ直下を想定。
5. **申請金額**: 1,110時間×2,100円＝2,331,000円で一致。公募要領の時間単価・上限に準拠。
6. **プロジェクト名の字数**: 公募要領では「30字以内」。現タイトル「潜在空間ベクトルとルールベースを統合したOTC医薬品推奨システムの実装」は30字を超える。Google Forms 等で入力する「プロジェクト名」欄には30字以内に収める必要がある。提案詳細資料のタイトルとしては問題なし（様式上の制限は主にForms用）。

### 様式面
7. **ページ数**: 8ページ。竹内PM「A4・10.5pt以上・8ページ程度（10ページ以内）」に合致。
8. **冒頭の開発テーマ名・提案者名**: 記載済み。
9. **提出前チェックリスト**: 竹内PM.md の各項目を提出前に再確認すること。

## 4. 良かった点（維持推奨）

- **① 何を作るか**: 背景・目的・目標が明確。「何をどこまで作るか」が1文で分かる。
- **「人が誤らないための構造」**: 提案者の哲学が伝わり、技術方針と一貫している。
- **図の活用**: システム構成・データフロー・5層防御・ガントチャートを掲載しており、ビジュアルで理解しやすい。
- **数理的安全性**: 5層防御・ハイブリッドスコアの式を明示し、技術力が伝わる。
- **登録販売者＋ドラッグストア経験**: 課題感と解決策の接点が明確。
- **受賞歴・資格**: 腕前の証明として十分。
- **評価指標の表**: 安全性・品質・パフォーマンスを数値目標で示しており、計画の具体性が高い。
