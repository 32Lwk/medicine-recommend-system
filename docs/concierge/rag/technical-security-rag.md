# 技術セキュリティ FAQ — RAG 最適化版

> データ保存・プライバシー・LINE 経路・開示境界の横断 FAQ。
> BM25 retrieve 用。ユーザー向け回答では env 名を出さない。例文に PII を含めない。

## Q: チャットの会話は保存されますか

<!-- rag-keywords: チャット 会話 保存 履歴 残る メッセージ -->

**回答要点**

- **Yes**: Web・LINE いずれも PostgreSQL にセッションとメッセージを保存
- **目的**: 会話再開・推奨精度・試験運用の品質改善（プライバシーポリシー第3条）
- **正本（条項）**: `docs/public/プライバシーポリシー.md` — direct intent では全文参照
- **正本（技術）**: `04-data-security.md`

## Q: チャット保存とプライバシーポリシーの関係を教えてください

<!-- rag-keywords: チャット 保存 プライバシー 横断 ポリシー データ 個人情報 関係 -->

**回答要点**

- **技術面**: メッセージ・属性は PostgreSQL に保存（04-data-security）
- **運用・法的面**: 何を取得し何目的で使うかはプライバシーポリシー第2・3条が定義
- **Concierge の役割分担**: architecture = 保存先概要 / doc_privacy = 条項に基づく回答（paraphrase 禁止）
- **削除**: LINE はチャット内依頼可、その他は第7条連絡先
- **関連**: `00-disclosure-policy.md`（横断質問）

## Q: 氏名や住所は収集しますか

<!-- rag-keywords: 氏名 住所 電話 収集 個人情報 直接 特定 -->

**回答要点**

- **原則 No**: 氏名・住所・電話番号など個人を直接特定できる情報は原則収集しない（プライバシーポリシー第2条）
- **収集する例**: 症状、年齢層、性別、アレルギー、併用薬、利用ログ
- **LINE**: userId は生値ではなくハッシュ化または仮名 ID として扱う
- **正本**: doc_privacy intent

## Q: 症状や年齢の情報はなぜ保存するのですか

<!-- rag-keywords: 症状 年齢 なぜ 保存 理由 属性 妊娠 アレルギー -->

**回答要点**

- **Why**: 市販薬推奨の安全性・提案品質のため（第3条）
- **What**: セッション内の user_attributes および LINE 長期記憶（属性・要約）
- **期間**: LINE 長期記憶は相談継続のため一定期間保持。削除請求可（第5・7条）
- **関連**: `04-data-security.md`

## Q: データの削除や訂正はできますか

<!-- rag-keywords: 削除 訂正 開示 請求 データ 消して 記憶 -->

**回答要点**

- **権利**: テスターは開示・訂正・削除を請求可能（第7条）
- **LINE**: チャット内で相談記憶・属性の削除依頼
- **その他**: 不具合報告フォームまたはメール（第7条記載の連絡先 — doc_privacy / doc_operator カードで正確に案内）
- **技術**: MemoryDeleteAgent が削除意図を処理

## Q: 運営者の名前や所属を教えてください

<!-- rag-keywords: 運営者 名前 所属 大学 誰 開発者 個人情報 開示 -->

**回答要点**

- **チャット回答**: 氏名・所属・学年・資格は **開示しない**（doc_operator ルール）
- **理由**: プライバシー保護のため（利用者に配慮した1文）
- **案内するもの**: β版試験運用の個人開発、問い合わせ窓口（フォーム・メール — doc 表記のまま）
- **境界**: ℹ️ モーダルの運営者情報 doc には公開情報として記載。チャット LLM 生成文とは別レイヤ
- **関連**: `00-disclosure-policy.md`

## Q: なぜチャットでは運営者の個人情報を教えないのですか

<!-- rag-keywords: なぜ 運営者 個人情報 教えない 開示 しない 理由 -->

**回答要点**

- **方針**: Concierge の doc_operator intent で PII 非開示を強制
- **理由の述べ方**: 「プライバシー保護のため」等、利用者に配慮した表現
- **連絡手段**: 個人名の代わりに公式の問い合わせ窓口を案内
- **sanitize**: 出力に氏名・大学・学年パターンが混入した場合は除去
- **関連**: `concierge_agent.py` doc_operator 要件

## Q: LINE と Web でデータの扱いは違いますか

<!-- rag-keywords: LINE Web 違い データ 保存 長期記憶 セッション -->

**回答要点**

- **共通**: PostgreSQL 保存、同一 Chat Pipeline v2
- **LINE のみ**: `line:{userId}` セッション、長期記憶（属性・相談要約）、表示 24 件 trim
- **Web のみ**: 引き継ぎなしセッションには長期記憶なし
- **引き継ぎ**: LINE → Web ワンタイムトークン（短期）
- **関連**: `06-line-gcp-path.md`、`04-data-security.md`

## Q: LINE からのメッセージはどこで処理されますか

<!-- rag-keywords: LINE メッセージ 処理 どこ webhook Cloud Run GCP サーバ -->

**回答要点**

- **経路**: LINE Platform → Webhook → GCP Cloud Run 本番（medicine.yutok.dev）
- **手順**: 署名検証 → 即 200 → 去重 → 非同期で Chat Pipeline v2
- **AWS**: LINE Webhook は向けない（Web 試験用ステージングのみ）
- **関連**: `06-line-gcp-path.md`

## Q: LINE Webhook は安全ですか（署名・再送）

<!-- rag-keywords: LINE webhook 安全 署名 検証 再送 セキュリティ -->

**回答要点**

- **署名**: Channel Secret で `X-Line-Signature` を検証。不一致は 403
- **再送対策**: 検証成功後すぐ 200 を返し、処理はバックグラウンド
- **去重**: 同一 webhook イベント ID の二重処理を防止
- **秘密値**: Channel Secret / Access Token は利用者向け回答に出さない

## Q: GCP 本番と AWS ステージングで利用者データは共有されますか

<!-- rag-keywords: GCP AWS 共有 データ 別 混在 データベース -->

**回答要点**

- **No**: DB インスタンス・ログは完全に分離
- GCP 本番 = Neon PostgreSQL + Cloud Logging
- AWS ステージング = 別 PostgreSQL + CloudWatch Logs
- 共通は医薬品画像 CDN URL のみ
- **関連**: `01-cross-cloud-architecture.md`

## Q: API キーやデータベースのパスワードは漏れませんか

<!-- rag-keywords: API キー パスワード 漏洩 シークレット 安全 データベース -->

**回答要点**

- Secrets は Secret Manager 経由でサーバ注入。チャット・公開 API には含めない
- Concierge 出力サニタイズで env 名・接続文字列パターンを除去
- `/health` は status と git commit のみ
- 非公開情報を聞かれた場合は「公開されている範囲では」と述べる

## Q: 匿名加工情報とは何ですか

<!-- rag-keywords: 匿名加工 統計 個人 特定 できない 匿名 -->

**回答要点**

- **定義**: 個人を特定できないよう加工した情報（プライバシーポリシー第6条）
- **用途**: 統計処理・サービス改善・学術的検討
- **第三者提供**: 再識別不可の形式を維持
- **正本**: doc_privacy intent — 条項を創作しない

## Q: 管理画面から利用者のチャットは見えますか

<!-- rag-keywords: 管理画面 オペレーター 閲覧 見える admin セッション -->

**回答要点**

- **試験運用**: admin_chat からオペレーターがセッション閲覧可能
- **目的**: 不具合調査・試験運用の品質確認
- **方針**: 本番利用者データの取扱いはマスク方針に従う（04-data-security）
- **関連**: `docs/security/ADMIN_PII_PLAYBOOK.md`（内部運用）

## Q: 入力した内容がブロックされることはありますか

<!-- rag-keywords: ブロック 入力 脅迫 違法 abuse 禁止 -->

**回答要点**

- **Yes**: 脅迫・違法薬物・システム abuse 等はカテゴリ別応答でブロック
- **目的**: 利用者・運営双方の安全
- 通常の症状・市販薬相談は Physical 経路で処理
- **関連**: security_validator / input_block_responses

## Q: ログにチャット内容は残りますか

<!-- rag-keywords: ログ チャット 内容 Cloud Logging CloudWatch 残る -->

**回答要点**

- **実行ログ**: GCP Cloud Logging / AWS CloudWatch Logs にアプリログ
- **用途**: 障害調査・運用監視
- **開発 eval**: リポジトリ `log/` に分析 JSONL（本番 PII はマスク方針）
- 利用者向け回答ではログ基盤の内部名を列挙しない

## Q: 第三者にデータを提供しますか

<!-- rag-keywords: 第三者 提供 共有 売る 外部 渡す -->

**回答要点**

- **原則 No**: 法令に基づく場合または本人の明確な同意がある場合を除く（第4条）
- **匿名加工情報**: 第6条の条件で利用・提供の可能性
- **正本**: doc_privacy intent
- 具体的な委託先一覧をドキュメントに無い場合は推測で補わない

## Q: 試験運用終了時にデータはどうなりますか

<!-- rag-keywords: 試験運用 終了 停止 削除 匿名化 データ -->

**回答要点**

- **方針**: 提供停止時、法令上保存が必要な場合を除き、個人を特定しうる情報は速やかに削除または匿名化（第5条3項）
- **正本**: doc_privacy intent
- 具体的な日数がドキュメントに無い場合は「ポリシー記載のとおり」と述べ、創作しない
