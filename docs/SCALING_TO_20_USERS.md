### 戦略2: Gevent（非同期処理）の導入

#### 概要

`gevent`を使用することで、1つのワーカーで複数のリクエストを並行処理できます。I/O待機（ChatGPT API呼び出し、データベースクエリ）が多い処理に適しています。

#### 構成

**構成**:
- **プラン**: Hobby Plan - Starter → **Standard Plan**（1 CPU, 1GB RAM per instance）
- **インスタンス数**: 2 → **3-4インスタンス**
- **ワーカー数**: 2 → **5 per instance**
- **ワーカークラス**: sync → **gevent**
- **合計ワーカー数**: 4 → **15-20ワーカー**
- **同時処理数**: 4 → **60-100リクエスト**（1ワーカーあたり4-5リクエスト）

**設定**:
```bash
# 環境変数
GUNICORN_TIMEOUT=120
GUNICORN_GRACEFUL_TIMEOUT=30
GUNICORN_WORKERS=5          # 5ワーカー per instance
GUNICORN_WORKER_CLASS=gevent  # 非同期処理

# 期待値
- 同時アクセス数（ピーク）: 20-25人
- 1時間あたりの処理能力: 約3,000-4,000リクエスト
- 1日あたりの処理能力: 約72,000-96,000リクエスト
```

**必要なパッケージ**:
```bash
pip install gevent
```

**requirements.txtへの追加**:
```
gevent==24.2.1
```

**メリット**:
- メモリ効率が良い（ワーカー数が少なくて済む）
- I/O待機中に他のリクエストを処理できる
- コスト効率が良い

**デメリット**:
- CPU集約的な処理には不向き
- デバッグが難しい場合がある
- コードの互換性確認が必要

### ステップ3: Geventの導入（オプション）

#### 3.1 パッケージの追加

```bash
# requirements.txtに追加

```

#### 3.2 コードの互換性確認

`gevent`を使用する場合、以下の点を確認:

1. **モンキーパッチング**: `gevent`は自動的に標準ライブラリをパッチします
2. **データベース接続**: `psycopg2`は`gevent`と互換性があります
3. **HTTPリクエスト**: `httpx`や`requests`は`gevent`と互換性があります

#### 3.3 環境変数の設定

```bash
# Render.comの環境変数
GUNICORN_WORKERS=5
GUNICORN_WORKER_CLASS=gevent
```

## トラブルシューティング

### 問題1: Geventの互換性エラー

**症状**: `gevent`を使用した際にエラーが発生

**解決方法**:
1. 必要なパッケージがインストールされているか確認
2. モンキーパッチングが正しく動作しているか確認
3. データベース接続が`gevent`と互換性があるか確認

### 問題2: メモリ不足

**症状**: `MemoryError` または `Out of memory`

**解決方法**:
1. ワーカー数を減らす
2. より多くのメモリを持つプランにアップグレード
3. メモリリークを確認

### 問題3: データベース接続プールの枯渇

**症状**: データベース接続エラー

**解決方法**:
1. 接続プールの最大数を増やす
2. 接続のタイムアウトを調整
3. PostgreSQLの最大接続数を確認
