## 4. 根本原因仮説

### 4.1 意図不一致警告（primary — 分析パイプライン側）

**根本原因**: ヒューリスティック `greeting_to_non_greeting` が `input_labels` の `general` ラベルのみを根拠に判定しており、「こんにちは」「お元気ですか」等を含むカジュアル挨拶パターンを greeting として認識していない。

**裏付け**:

- 実行パイプライン（triage → intent_router → concierge greeting）は全段階で greeting と一致
- `dialogue_route_shadow.mismatch=false`
- ボット応答は入力の挨拶・近況確認に正しく応答

**結論**: ユーザー体験上の意図不一致は**発生していない**。問題は品質分析ヒューリスティックの精度。

### 4.2 レイテンシ（secondary — 本番 UX）

**根本原因**: 低リスクの `Other/general_other` 入力でも、フル triage（2 段 LLM）＋長時間 safety_gate が必ず走る設計。挨拶 fast-path が未適用。

**数値根拠**:

- `before_orchestrator` まで 13.6 s（concierge 生成前）
- safety_gate 9.7 s > triage 5.9 s > concierge_build 2.0 s

### 4.3 コスト（tertiary）

挨拶 1 ターンで LLM 4 呼び出し・約 ¥0.27。トラフィック増加時に積み上がる構造。
