## Root cause hypothesis（根本原因仮説）

### 1. ヒューリスティック false positive（side_effect_qa_mishandled）

`session_conversation_analysis.py` の判定は `routing.sub_route` が未設定の場合、triage subcategory（`medication_side_effect`）と gate 名（`medicine_side_effect_qa`）の不一致を検出し、さらに応答中の「眠気」「相談してください」が `looks_escalation` パターンにマッチして critical 化する。Shadow Router は正しく `medicine_side_effect_qa` を解決しており、実行結果も副作用 Q&A カード。**分析基盤の判定ロジックが実ユーザー体験と乖離**している。

### 2. バファリン製品特定の非決定性（medicine_qa LLM）

ユーザーは「バファリン」と総称したが、ターン 4 は **バファリンA**、ターン 5 は **バファリンプレミアム** を代表製品として回答。いずれも OTC バファリンシリーズの valid な選択だが、**同一セッション・同一質問で比較対象が変わる**ため、ユーザーは回答の信頼性を疑い **24.7 時間後に同一質問を再送**した可能性が高い。根本原因は `medicine_response_builder` が generic ブランド名に対し **製品ラインを固定せず LLM が都度選択**していること。

### 3. conversation_history の sage_qa プレースホルダ

ターン 1–2 の `conversation_history` には応答本文ではなく `sage_qa` が保存される。マージ後のセッション `conversation_history` には同一 user 発話が重複記録され、**分析上 5 ターンに見える**ほか、後続ターンの LLM プロンプト（ターン 5: 1,390 prompt tokens）にノイズを載せている。

### 4. medicine_qa の高 E2E レイテンシ（37 s）

ターン 2/4 の `phase_summary_ms` 合計は約 5.5 s だが E2E は 37 s。`breakdown_ms.before_orchestrator` は 6.8 s 時点で記録が止まり、**ストリーミング完了〜クライアント反映までの区間が計測外**、または **answer_stream の待ち**が支配的と推定。ユーザー体感として初回 medicine_qa は非常に遅い。

### 5. triage subcategory の粒度不足

医薬品比較 Q&A が triage 上 `general_other` のまま shadow gate で `medicine_qa` に矯正されている。機能上は問題ないが、**ログ分析・ダッシュボードで intent 分布が歪む**。

## Recommended actions（推奨アクション）

### P0 — 応答品質（ユーザー影響大）

1. **generic ブランド名の製品固定ルール**  
   「バファリン」等の総称入力時は、比較表で **同一製品ライン**（例: バファリンA / バファリンプレミアム / バファリンEX）を明示し、セッション内で一貫させる。または「どのバファリン製品か」を 1 問確認してから比較する。

2. **medicine_qa プロンプトに「前ターンと同一製品を使う」制約**  
   ターン 5 のように履歴参照時、前回回答で特定した製品名を優先。不一致時は「前回はバファリンA と説明しましたが、バファリンシリーズには複数製品があります」と明示的に補足。

### P1 — ヒューリスティック・分析基盤

3. **`side_effect_qa_mishandled` false positive 解消**  
   - `routing.sub_route` 未設定時は `dialogue_route_shadow.sub_route` をフォールバック  
   - 副作用 Q&A 標準免責（「眠気」+「薬剤師・医師に相談」）を `looks_escalation` から除外  
   - `render=sage_qa` / `diagnosis.kind=medicine_qa` の場合は issue を出さない

4. **`turns[].routing` への shadow 結果伝播**  
   merge 時に `sub_route`・`resolved_by`・`source` を含め、セッション分析 CLI の判定精度を向上。

### P2 — パフォーマンス・観測

5. **medicine_qa E2E 37 s の区間計測追加**  
   `before_orchestrator` 以降〜`answer_stream` 完了までの breakdown マーカーを追加し、ボトルネック（LLM ストリーム / DB / 外部 API）を特定。

6. **conversation_history マージの重複排除**  
   同一 trace の user 発話二重記録を防ぎ、プロンプト token 増と分析ノイズを削減。

### P3 — triage 命名整合

7. **triage subcategory の medicine_qa 系統一**  
   医薬品比較・副作用 Q&A を `general_other` ではなく `medicine_qa` / `medication_side_effect` 等に細分化し、shadow gate 名と近接させる。
