## 5. 根本原因仮説

### 5.1 主要因（ターン 2/4 の意図不一致）

1. **`layer1_side_effect_qa` gate の過剰マッチ**  
   「ロキソニン」を含む入力に対し、直前ターンが副作用 Q&A である文脈下で、比較質問（「〜と〜の違い」）でも副作用 gate が先にヒットした。トリアージ `general_other` より gate 解決が優先され、最終ルートが `medicine_side_effect_qa` に固定された。

2. **gate 優先順位の問題**  
   正常系（`1784950060148999624099`）では同一 triage `general_other` が `layer1_medicine_qa` に解決。本セッションでは `layer1_side_effect_qa` が勝利 — **比較構文（「違い」「と」）の否定条件**または **medicine_qa gate の優先度**が不足。

3. **応答テンプレートの固定**  
   `medicine_side_effect_qa` ハンドラは製品名（ロキソニン S）を抽出し副作用 CSV を返す設計。比較対象（イブ）が入力にあっても無視され、単品副作用ダンプになる。

4. **shadow mismatch 検出の盲点**  
   `dialogue_route_shadow` は triage `general_other` × sub_route `medicine_side_effect_qa` を `mismatch=false` と記録。比較 Q&A と副作用 Q&A の組み合わせを regression として検出できていない。

### 5.2 副次要因（分析・観測）

5. **ヒューリスティック false positive（ターン 3）**  
   `side_effect_qa_mishandled` が適切な副作用 Q&A を critical 判定。`routing.sub_route` 未マージと安全フッター文言が誤発火。本当の問題（ターン 4）を埋もれさせるリスク。

6. **conversation_history の sage_qa プレースホルダ**  
   分析上 4 ターンに見えるが実質 2 問。ログマージ artefact がセッション評価を複雑化。

7. **パフォーマンス**  
   E2E 7.5–8.8 s。副作用 Q&A は gate 早期解決でも safety_gate 3.4–4.5 s が支配的。品質問題ではないが UX レイテンシは改善余地あり。

## 6. 推奨アクション

### P0 — ルーティング修正（ユーザー影響）

1. **`layer1_side_effect_qa` に比較構文の除外ルールを追加**  
   「〜と〜の違い」「比較」「どっち」等 + 複数 OTC 名が共存する入力は `layer1_medicine_qa` へ委譲。トリアージ `general_other` との整合を gate 段階で強制。

2. **gate 優先順位の見直し**  
   比較 Q&A パターンでは `layer1_medicine_qa` > `layer1_side_effect_qa`。直前ターンが副作用 Q&A でも、現ターンの構文が比較なら medicine_qa を優先。

3. **shadow mismatch 条件の拡張**  
   triage `general_other` + sub_route `medicine_side_effect_qa` を **regression** として `mismatch=true` に昇格。アラート・テストケース化。

### P1 — 応答品質

4. **`medicine_side_effect_qa` ハンドラに比較入力ガード**  
   複数製品名検出時は副作用 CSV 返却を中止し、`medicine_response_builder` または比較専用テンプレへフォールバック。

5. **回帰テスト追加**  
   シナリオ: 「ロキソニンって眠くなる？」→「ロキソニンとイブの違いって何？」  
   期待: 2 問目は主成分比較（`1784950060148999624099` と同等品質）。

### P2 — 分析・ヒューリスティック

6. **`side_effect_qa_mishandled` 判定の修正**  
   `dialogue_route_shadow.sub_route=medicine_side_effect_qa` かつ diagnosis.kind=medicine_qa の場合は critical を出さない（`1784946740773995708821` と同型修正）。

7. **`routing.sub_route` の turn マージ**  
   shadow 結果を `turns[].routing.sub_route` に反映し、ヒューリスティックと LLM 分析の整合性を向上。

8. **conversation_history dedupe**  
   同一 trace の sage_qa プレースホルダと最終本文の二重記録をエクスポート時に統合。

### P3 — パフォーマンス監視

9. **副作用 Q&A gate hit 時の safety_gate プロファイル**  
   gate 早期解決後も 3–5 s の safety_gate 待ちが発生。ボトルネック区間の継続計測。
